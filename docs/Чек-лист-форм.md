# Чек-лист конвенций форм

Документ фиксирует единые правила доработки управляемых форм справочников и документов конфигурации «КурсоваяРабота». Источник — `openspec/changes/form-ux-adaptation/design.md` (решения D3, D9, D10).

## Палитра условного оформления

| Смысл | Фон | Текст |
|---|---|---|
| Ошибка: просрочка, тяжёлый инцидент, отклонённая претензия, отрицательное значение | `#FFC7CE` | `#9C0006` |
| Предупреждение: расхождение, ожидание ответа, несогласованная корректировка | `#FFEB9C` | `#9C0006` |
| Успех: оплачено, согласовано, завершено | `#C6EFCE` | `#006100` |
| Нейтральное: отменено, завершено как архив | `#EDEDED` | `#7F7F7F` |

Правила декларативные: не изменяют данные, не блокируют открытие формы и запись.

Текст на жёлтом фоне предупреждения — тёмно-красный `#9C0006`, а не приглушённый `#9C6500`: решение принято при настройке правил ради читаемости (коммит `39398f1`). Фон и остальные цвета соответствуют палитре.

## Имена и свойства групп

- Карточка: `ГруппаШапка` → ключевые реквизиты; «Основное» (страница или группа) → табличные части и основной текст.
- **Свёрнутая группа «Дополнительно» реализована только в трёх формах** — `ЗаявкаТуристаНаМаршруте`, `Инцидент`, `ПодтверждениеУслуги`. В остальных карточках второстепенные реквизиты остаются в шапке, плоской раскладкой; пустые оболочки `ГруппаДополнительныеРеквизиты` 1С не отображает, поэтому групп там не видно. Отклонение от D9 согласовано с заказчиком 2026-10-20 (в группах оказывалось по одному-два поля).
- Группа «Дополнительно»: заголовок «Дополнительно», сворачиваемая, свёрнута при открытии.
- Все формы объектов: `AutoMarkIncomplete` = Истина.
- Обязательные реквизиты (`FillChecking = ShowError`) — в шапке или первой группе, выше необязательных того же блока.
- `Комментарий` остаётся в подвале области «Основное» (решение заказчика по этапу 3).
- `СуммаДокумента` — вычисляемый итог табличной части; в шапке `ЗаказПоставщику` и `ПодтверждениеУслуги`, только для чтения, в группу «Дополнительно» не убирается.
- Имена табличных частей не переименовываются: `ПодтверждённыеУслуги` сохраняет «ё».

## Правила подсказок

- Подсказка обязательна для каждого обязательного реквизита.
- Подсказка обязательна для полей с неочевидной семантикой: `ДатаОжиданияПодтверждения`, `СрокSLA`, `РезультатСверки`, `Источник`, `СогласованоРуководителем`, `БуферДоСледующегоМинут`, `ПроцентШтрафа`, `МаксимальнаяКомпенсация`, `ПорогСогласованияРуководителем`, `SLAЧасов`, `ТиповойПроцентКомпенсации`, `СуммаДокумента`.
- Текст — деловой, из формулировок раздела 5 Дополнения к ТЗ; новых правил не выдумывать.
- Пустых автогенерированных `РасширеннаяПодсказка` у видимых полей быть не должно.

## Навигация подсистем

19 листовых подсистем получили `Ext/CommandInterface.xml`. В панели навигации выводится команда открытия списка каждого объекта подсистемы; служебные регистры и ПВХ скрыты.

**«Создать …» в панели навигации не выводится.** Стандартную команду создания платформа в панель навигации не помещает: проверены три варианта записи — `CommandsPlacement` с `Placement=Auto`, с `Placement=Manual` и без `Placement` вовсе. `Task.ЗадачаИсполнителя` в «Сервисе» оставлена видимой по решению D8 (задачи — предмет раздела), остальные служебные объекты скрыты.

**ПВХ и перечисления.** Планы видов характеристик (`ChartOfCharacteristicTypes`) стандартную команду открытия списка имеют — записи о скрытии `ДополнительныеРеквизитыТуриста` и `ДополнительныеРеквизитыУслуг` платформа принимает. А у `Enum` и `Constant` такой команды нет: платформа отвергает `StandardCommand.OpenList` с ошибкой «Неизвестная команда» при загрузке конфигурации. В панель навигации перечисления и константа не попадают, поэтому в «Сервисе» они не скрываются.
