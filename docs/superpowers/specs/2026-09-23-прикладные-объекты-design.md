# Дизайн: прикладные объекты конфигурации «КурсоваяРабота»

- Дата: 2026-09-23
- Задача: создать прикладные объекты этапа 2 в соответствии с ТЗ (структура конфигурации).
- Источники: `Техническое задание.doc` (основное), `Дополнение к ТЗ.docx` (разделы 4, 5, 9 — детальная модель).
- Инструмент: скилл `meta-compile` (генерация XML-исходников в `src/КурсоваяРабота`), проверка — `meta-validate` + `cf-validate`.
- Загрузка в информационную базу в объём задачи не входит (решение заказчика).

## 1. Принятые решения по расхождениям ТЗ

1. **Источник состава** — Дополнение к ТЗ (детальные поля раздела 4, состав разделов 5 и 9).
2. **«СобытиеМаршрута»** — отдельный документ (его нет в разделе 4, но он есть в разделах 1, 2, 9 и на него ссылается ТЧ «Изменения» документа «КорректировкаМаршрута»). У документа «МаршрутныйЛист» табличная часть «События» удалена, движений нет.
3. **«ГрафикПеремещений»** — регистр сведений вместо регистра накопления: ресурсы-даты недопустимы в регистре накопления (ресурсы только числовые). Периодический (день), подчинение регистратору. Дополнительно к списку ТЗ добавлено измерение «СобытиеМаршрута» — иначе сторно при корректировке не может точно сослаться на исходное событие.
4. **«СрокиКонтроля»** — независимый непериодический регистр сведений (в разделе 4 указано «подчинение регистратору», но ни один документ его не двигает); заполняется администратором вручную.
5. **Служебные объекты**, которых нет в списках ТЗ, но без которых не работает заявленная функциональность:
   - константа «ПорогСогласованияРуководителем» (Number(15,2), упомянута в п. 5.1.7, 5.4.3);
   - задача «ЗадачаИсполнителя» + регистр сведений «АдресацияЗадач» (измерение Исполнитель: СправочникСсылка.Сотрудники) — платформа требует задачу для бизнес-процессов, а адресация задач возможна только через регистр адресации.
6. **Подчинённые справочники** («ДоговорыСПоставщиками», «ОбъектыГостеприимства») — через стандартное владение (Владелец: Поставщики), отдельный реквизит «Поставщик» не дублируется.
7. **Нумерация**: периодическая (год) — только у документов; у справочников периода нумерации платформа не поддерживает, будет автонумерация без периода.
8. **Поля «ФИО»** (Туристы, Сотрудники) — отдельные реквизиты по разделу 4; стандартное «Наименование» сохраняется.
9. **Минимальные НСИ** (в ТЗ не детализированы): СтраныМира — только стандартные Код/Наименование; Валюты — Код(3)/Наименование; Пользователи — Наименование + ИмяПользователяИБ String(64); ЕдиницыИзмерения — стандартные Код/Наименование.
10. **Бизнес-процессы** создаются как каркасы: карта маршрута пустая (инструмент не генерирует точки), точки наносятся в Конфигураторе на этапе 4 плана ТЗ.
11. **Ограничение файловой ИБ (1024 символа)**: поля «Инцидент.Описание» и «Инцидент.ТекстИИ» вместо Строка(2000) из раздела 4 Дополнения сделаны строками неограниченной длины — файловая база не принимает строки длиннее 1024 («Слишком большое значение описателя длины»). Неограниченная длина сохраняет длинные тексты; проверено загрузкой конфигурации в базу и `/CheckConfig`.
