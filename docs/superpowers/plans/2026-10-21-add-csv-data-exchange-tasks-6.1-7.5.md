# Обмен данными через CSV — заказы поставщику — План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: используйте `/opsx-executing-plans add-csv-data-exchange` для реализации плана по задачам. Шаги отмечены чекбоксами (`- [ ]`).

**Goal:** Добавить в обработку выгрузку заказов поставщику за период и загрузку их обратно — плоским файлом, с группировкой строк в документ, пересчётом суммы и атомарной записью документа.

**Architecture:** Формат плоский: одна строка файла — одна строка ТЧ `Услуги`, шапка повторяется. Загрузка строит `Соответствие` ключ → массив строк, затем для каждого ключа собирает документ целиком: шапка из первой строки группы, ТЧ из всех строк группы, `СуммаДокумента` — сумма строк. Документ пишется одной транзакцией, поэтому «полудокумента» в базе не бывает.

**Tech Stack:** 1С:Предприятие 8.3.27.1786, `ОбменCSV`, модуль `РасчётКомпенсаций`, драйвер `ТестОбмена`, PowerShell.

**Spec:** `openspec/changes/add-csv-data-exchange/specs/data-exchange/spec.md` (выгрузка заказов, частичная загрузка, правила записи), `openspec/changes/add-csv-data-exchange/design.md` (решения 3, 5, 8)

## Global Constraints

- Платформа `8.3.27.1786`, файловая ИБ `db/КурсоваяРабота`, тонкий клиент.
- Формат обмена: UTF-8 с BOM, `;`, десятичная запятая, даты `ГГГГ-ММ-ДД`, булево `Истина`/`Ложь`.
- `СуммаДокумента` в файл не пишется и при загрузке пересчитывается как сумма строк ТЧ.
- `Сумма` строки выгружается для наглядности и при загрузке пересчитывается через `РасчётКомпенсаций.РассчитатьСуммуСтроки(Количество, Цена)`.
- `ОбменДанными.Загрузка` не выставляется нигде.
- Документ пишется одной транзакцией целиком.
- Тестовые объекты: номер с префиксом `ТЕСТ-`, наименование услуг с префиксом `ТЕСТ-`.
- `ТекущаяДатаСеанса()` только в серверном контексте.
- Команды к базе — `-UserName "Администратор"`.
- Лицензия на одно место: перед прогоном закрыть все сеансы 1С.
- Коммиты — английские conventional-сообщения.

## Review Focus

- **Один и тот же номер с двумя разными датами в файле** — при периодичности нумерации «год» это либо порча файла, либо склейка двух документов. Ожидаемое поведение: ошибка на весь номер, документ не пишется.
- **Документ из одной строки ТЧ** — самый частый случай в тестовых данных, и именно он ломает наивную группировку «все строки кроме первой — продолжение». Ожидаемое поведение: документ с одной строкой создаётся корректно.
- **Порядок строк в файле перемешан** — документы идут не подряд, строки одного заказа разбросаны. Ожидаемое поведение: группировка по ключу, а не по соседству строк.
- **Договор принадлежит другому поставщику** — наименование договора существует, но не у этого поставщика. Ожидаемое поведение: ошибка строки с указанием принадлежности, а не «не найдено».
- **Пустой файл заказов** — вердикт `PASS`, ни одного документа. Ожидаемое поведение: не `FAIL` и не исключение.
