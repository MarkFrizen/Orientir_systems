# Обмен данными через CSV — загрузка номенклатуры — План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: используйте `/opsx-executing-plans add-csv-data-exchange` для реализации плана по задачам. Шаги отмечены чекбоксами (`- [ ]`).

**Goal:** Научить обработку принимать CSV с номенклатурой услуг: проверять заголовок, типы, ссылки и уникальность, применять правила записи объекта, писать частично и выдавать отчёт с тремя вердиктами.

**Architecture:** Вся загрузка строится как конвейер над одной строкой файла: заголовок → типы → ссылки → уникальность → сборка объекта → `ПравилаЗаписи` → запись в транзакции. Каждая ступень добавляет свой класс ошибок в общий отчёт, не ломая предыдущие. Отчёт — единая структура `НовыйОтчёт()`, которую наполняют все ступени.

**Tech Stack:** 1С:Предприятие 8.3.27.1786, `ОбменCSV`, внешняя обработка-драйвер `ТестОбмена`, PowerShell.

**Spec:** `openspec/changes/add-csv-data-exchange/specs/data-exchange/spec.md` (требования про заголовок, типы, ссылки, дубли, правила записи, частичную загрузку и вердикты), `openspec/changes/add-csv-data-exchange/design.md` (решения 4, 5, 6, 7, 8, 9, 10)

## Global Constraints

- Платформа `8.3.27.1786`, файловая ИБ `db/КурсоваяРабота`, тонкий клиент.
- Формат обмена: UTF-8 с BOM, `;`, десятичная запятая, даты `ГГГГ-ММ-ДД`, булево `Истина`/`Ложь`.
- Доменная логика живёт только в `DataProcessors/ОбменСФайлами/Ext/ObjectModule.bsl`; `ОбменCSV` про номенклатуру не знает.
- `ОбменДанными.Загрузка` не выставляется нигде — загрузка проходит обычные проверки.
- Каждая единица обмена пишется в собственной транзакции.
- Тестовые объекты: наименование с префиксом `ТЕСТ-`, код из диапазона `999000001`–`999999999`.
- `ТекущаяДатаСеанса()` только в серверном контексте.
- Исходники и файлы для 1С — UTF-8; JSON/PS1 — UTF-8 с BOM.
- Команды к базе — `-UserName "Администратор"`.
- Лицензия на одно место: перед прогоном закрыть все сеансы 1С.
- Коммиты — английские conventional-сообщения.

## Review Focus

- **Код с ведущими нулями после Excel** — `000000042` превращается в `42`. Ожидаемое поведение: загрузка не молчит, а сообщает «код не найден» с исходным значением и подсказкой про формат ячейки.
- **Файл с одной строкой, где число полей меньше заголовка** — наивный разбор по индексам даст исключение вместо ошибки строки. Ожидаемое поведение: строка отклоняется с сообщением о числе полей, остальные грузятся.
- **Полностью пустой файл и файл только с заголовком** — не должны считаться ни успехом с данными, ни падением. Ожидаемое поведение: «обработано 0 строк», вердикт `PASS`, ни одного объекта не создано.
- **Дубль кода, который уже помечен на удаление** — элемент существует в базе. Ожидаемое поведение: это дубль, строка отклоняется; «оживить» помеченный элемент загрузка не пытается.
- **Ошибка записи в середине файла** — уже записанные элементы не должны откатиться. Ожидаемое поведение: записанные остаются, вердикт `ЧАСТИЧНО`, счётчики сходятся с числом строк.
