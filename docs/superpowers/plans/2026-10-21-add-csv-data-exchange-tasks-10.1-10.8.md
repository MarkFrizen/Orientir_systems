# Обмен данными через CSV — интеграционная проверка — План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: используйте `/opsx-executing-plans add-csv-data-exchange` для реализации плана по задачам. Шаги отмечены чекбоксами (`- [ ]`).

**Goal:** Прогнать полный набор проверок на собранной конфигурации, загрузить её в базу и подтвердить, что демо-набор, автотесты обмена и дымовые тесты остались зелёными.

**Architecture:** Никакого нового кода на этом этапе. План — последовательность гейтов: статические валидаторы → LSP → компиляция → загрузка в ИБ → три прогона (демо-набор, обмен, смоук) → документация. Каждый гейт блокирует следующий: нет смысла грузить в базу конфигурацию, которая не компилируется.

**Tech Stack:** 1С:Предприятие 8.3.27.1786, bsl-language-server, PowerShell, xddTestRunner.

**Spec:** `openspec/changes/add-csv-data-exchange/specs/data-exchange/spec.md`, `openspec/changes/add-csv-data-exchange/specs/demo-dataset/spec.md` (дельта про целевые количества)

## Global Constraints

- Платформа `8.3.27.1786`, файловая ИБ `db/КурсоваяРабота`, тонкий клиент.
- Команды к базе — `-UserName "Администратор"`, пароль пустой.
- Лицензия на одно место: перед каждым прогоном закрыть все сеансы 1С; после прогонов убивать сирот `1cv8*` с `*TestClient*` в командной строке.
- Бэкап `db/backup-2026-10-21-before-exchange.dt` из Task 2 — точка отката.
- LSP должен быть `ready` и `100` до запуска диагностики.
- PS1 и JSON — UTF-8 с BOM; XML — ровно один BOM.
- `ОбменДанными.Загрузка` не выставляется нигде.
- Коммиты — английские conventional-сообщения.

## Review Focus

- **Конфигурация загружена, но не обновлена** — объект есть в исходниках, а в базе его нет. Ожидаемое поведение: `db-load-xml` и `db-update` выполнены парой, объект открывается.
- **Сеанс 1С остался висеть после ручной проверки** — следующий прогон падает на занятой файловой базе. Ожидаемое поведение: проверка процессов перед каждым прогоном.
- **Правка исходников после загрузки** — тесты гоняют старую версию из базы. Ожидаемое поведение: прогоны идут строго после последней загрузки.
- **Диагностика LSP на непроиндексированном проекте** — пустой ответ читается как «ошибок нет». Ожидаемое поведение: `status: ready` проверен до прогона.
- **Документация обновлена до прогонов** — записан результат, которого ещё нет. Ожидаемое поведение: `docs/Оставшиеся-задачи.md` правится последней задачей, после зелёных прогонов.
