# Расчёты в формах и общие модули — план 1: подготовка и метаданные

> **For agentic workers:** REQUIRED SUB-SKILL: Use `/opsx-executing-plans form-calculations-and-shared-modules` to implement this plan task-by-task and sync progress back to OpenSpec. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подготовить рабочее окружение, снять базовую линию проверок, объявить три общих модуля и добавить реквизит `СуммаДокумента` в два документа — фундамент, на котором держатся все остальные планы.

**Architecture:** Метаданные правятся только через скиллы проекта (`meta-compile`, `meta-edit`, `form-edit`), которые переписывают XML-выгрузку в `src/КурсоваяРабота` и держат корректными UUID и порядок `ChildObjects`. Никакого ручного редактирования XML: двойной BOM и неверный порядок типов гарантированно ломают загрузку конфигурации. Проверка каждого шага — `cf-validate`/`meta-info`/`form-validate`, а не «на глаз».

**Tech Stack:** 1С:Предприятие 8.3.27, управляемое приложение, XML-выгрузка `src/КурсоваяРабота`, файловая ИБ `db/КурсоваяРабота`, MCP-инструменты `1c-lsp-diagnostics` и `1c-lsp-navigation`, скиллы проекта `db-dump-dt`, `meta-compile`, `meta-edit`, `form-edit`, `meta-info`, `cf-validate`, `form-validate`.

## Global Constraints

- Платформа 8.3.27, режим совместимости `Version8_3_27`, управляемое приложение, вариант скрипта — русский.
- ИБ файловая, `db/КурсоваяРабота`; клиент-сервер вне скоупа.
- Метаданные правятся только скиллами проекта; ручное редактирование XML запрещено.
- `ТекущаяДатаСеанса()` недоступна на тонком клиенте — даты только в `&НаСервере`.
- Строки модулей короче 1024 символов (ограничение файловой ИБ).
- JSON и PS1 сохраняются в UTF-8 с BOM; двойной BOM ломает XML.
- UUID роли `Администратор` не менять.
- Команды Конфигуратора запускаются с `-UserName "Администратор"`.
- LSP-сервер `lsp-skill-server.exe` запущен, `root_path` = `D:\Projects\1C_prj\7 семестр\Kursovaya`.
- Имена метаданных, реквизитов и процедур — русские; отступы — табы; комментарии — по-русски.

## Review Focus

- **Порядок `<ChildObjects>` в `Configuration.xml`.** Общий модуль, вставленный не на своё место в перечислении типов, валит разбор конфигурации — ожидается, что `cf-validate` проходит с первого раза.
- **Повторный запуск `meta-compile`.** На существующем имени скилл может добавить второй узел в `Configuration.xml` вместо правки — ожидается ровно три `<CommonModule>`.
- **Путь с пробелом и кириллицей (`7 семестр`).** Незакавыченный путь в командах Конфигуратора рвётся на пробеле — ожидается, что все вызовы заключают путь в кавычки.
- **Двойной BOM после правок.** Скиллы пишут файлы сами, но ручная правка `docs/*.md` и `*.ps1` может добавить лишний BOM — ожидается, что XML грузится без ошибок кодировки.
- **`СуммаДокумента` с `FillChecking = ShowError`.** Если флаг случайно выставлен, платформа будет требовать заполнить вычисляемый реквизит от пользователя — ожидается `DontCheck`.
