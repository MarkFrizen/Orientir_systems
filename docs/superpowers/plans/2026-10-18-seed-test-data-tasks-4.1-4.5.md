# Наполнение демо-данными — план 3: проверка данных (4.1–4.5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read-only инструмент, который за один прогон говорит «набор годен / не годен»: количества, ссылки, табличные части, правила п. 5.3 — с вердиктом и кодом возврата.

**Architecture:** Новая внешняя обработка `ПроверкаДанных` с тем же способом запуска, что у `ЗаполнениеНСИ`: `/Execute` + путь лога в `/C`, `ПриОткрытии` вызывает `ВыполнитьПроверку` и закрывает программу. PowerShell-обёртка `run-check.ps1` дописывает размер файла базы (из 1С его не прочитать) и транслирует вердикт в код возврата.

**Tech Stack:** 1С:Предприятие 8.3.27.1786, BSL, внешняя обработка `.epf`, PowerShell.

**Spec:** `openspec/changes/seed-test-data/specs/dataset-verification/spec.md`, `design.md` (решение 7)

## Global Constraints

- Проверка только читает: ни одного `Записать`, `Провести`, `Установить`.
- Вердикт — последняя строка лога: `ВЕРДИКТ: PASS` или `ВЕРДИКТ: FAIL`.
- `run-check.ps1` возвращает 0 при `PASS` и 1 при `FAIL`.
- Перед запуском 1С закрыть процессы `1cv8`, `1cv8c`, `1cv8s` (лицензия на одно место).
- Лог — UTF-8, путь без пробелов (страховка от разбора `/C`).
- `build/`, `*.epf`, `*.log` в `.gitignore` — коммитятся только исходники и скрипты.

## Review Focus

- **Повторный прогон.** Пользователь гоняет проверку дважды и ждёт одинаковый лог — задача 3.5.
- **Помеченный на удаление поставщик.** Проверка обязана это увидеть, а не молча пропустить — задача 3.3.
- **Перевёрнутый период в табличной части.** Даты живут в строках ТЧ, не в шапке — задача 3.4.
- **Ноль объектов.** На пустой базе проверка не должна падать с делением на ноль или пустой выборкой — задача 3.2.
- **Размер базы.** 1С не умеет читать свой `.1CD`, поэтому размер добавляет PowerShell — задача 3.1.

- [ ] **Step 3: Реализовать точку входа**

В модуле формы:

```bsl
&НаКлиенте
Процедура ПриОткрытии(Отказ)
	ВыполнитьПроверку(ПараметрЗапуска);
	ЗавершитьРаботуСистемы(Ложь);

```

`ВыполнитьПроверку(ПутьЛога)` на сервере: открывает `Новый ЗаписьТекста(ПутьЛога, "UTF-8")`, пишет шапку `=== Проверка демо-набора, <дата> ===`, вызывает `ПроверитьКоличества`, `ПроверитьСсылки`, `ПроверитьТабличныеЧасти`, `ПроверитьПравила`, пишет `ВЕРДИКТ: PASS` при нуле нарушений и `ВЕРДИКТ: FAIL` иначе, закрывает файл.

- [ ] **Step 4: Написать `run-check.ps1`**

Повторить структуру `run-fill.ps1` с отличиями:
- обработка `build\ПроверкаДанных.epf`;
- до запуска — размер: `[math]::Round((Get-Item (Join-Path $db.path '1Cv8.1CD')).Length / 1MB, 1)`;
- после запуска — дописать в лог строку `Размер ИБ: <X> МБ, порог 2048 МБ — в пределах лимита` либо `превышен`;
- прочитать лог, найти строку `ВЕРДИКТ:`, вернуть 1 при `FAIL`, 0 при `PASS`, 2 если вердикта нет.

- [ ] **Step 5: Собрать и прогнать**

Run: `epf-build` для `ПроверкаДанных`, затем `powershell -ExecutionPolicy Bypass -File epf/run-check.ps1; "EXIT=$LASTEXITCODE"`
Expected: лог создан, содержит шапку и строку вердикта, `EXIT` равен 0 или 1.

- [ ] **Step 6: Закоммитить**

