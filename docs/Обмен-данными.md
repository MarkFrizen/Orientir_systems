## Формат номенклатуры услуг

Файл формирует `Обработки.ОбменСФайлами.ВыгрузитьНоменклатуру(ПутьФайла)`, читает обратно
`ОбменCSV.ПрочитатьФайл(ПутьФайла)`. Строка разбирается `ОбменCSV.РазобратьСтроку(Текст, ";")`,
собирается `ОбменCSV.СобратьСтроку(Поля, ";")`.

### Общие свойства файла

| Свойство | Значение |
|---|---|
| Кодировка | UTF-8 **с BOM**: первые байты файла `EF BB BF` |
| Разделитель полей | `;` (точка с запятой), внутри поля — только в кавычках |
| Разделитель строк | CRLF (`0D 0A`); при чтении одиночный LF тоже принимается |
| Первая строка | заголовок, ровно 8 колонок в порядке ниже |
| Десятичный разделитель | запятая: `9000,00` |
| Разделитель групп разрядов | не используется никогда: `1234,50`, а не `1 234,50` (пробел/неразрывный пробел сделают число нечитаемым) |
| Знаков после запятой у цены | всегда два, формат `ЧДЦ=2;ЧН=0,00` (`85,00`, не `85`) |
| Формат дат | `ГГГГ-ММ-ДД`, например `2026-10-21` (в файле номенклатуры дат нет — правило общее для обмена) |
| Булево | `Истина` / `Ложь`; сокращения `True`/`1`/`Да` не принимаются |
| Пустое значение | пустое поле между разделителями: `;;` |

### Колонки

| № | Колонка | Источник в справочнике `НоменклатураУслуг` | Тип в файле | Правило заполнения |
|---|---|---|---|---|
| 1 | `Код` | `Код` (строка, 9) | строка из 9 цифр с ведущими нулями | например `000000017`; в пределах файла не повторяется |
| 2 | `Наименование` | `Наименование` | строка, непустая | полное наименование как в справочнике, без сокращений |
| 3 | `ЭтоГруппа` | `ЭтоГруппа` | `Истина` / `Ложь` | `Истина` — группа (папка), `Ложь` — позиция номенклатуры |
| 4 | `Родитель` | `Родитель.Наименование` | строка, может быть пустой | пусто у верхнего уровня; иначе **наименование** родительской группы. Связь восстанавливается по наименованию, а не по коду, поэтому наименования групп в файле должны быть уникальны |
| 5 | `ВидУслуги` | `ВидУслуги` (`ПеречислениеСсылка.ВидыУслуг`), через `Строка()` | строка; у группы пусто | одно из значений перечисления: `Виза`, `Номер`, `Питание`, `Страхование`, `Трансфер`, `Экскурсия` |
| 6 | `Единица` | `Единица` (`СправочникСсылка.ЕдиницыИзмерения`), через `Строка()` | строка; у группы пусто | представление единицы: `Штука`, `Ночь`, `День`, `Человек` |
| 7 | `БазоваяЦена` | `БазоваяЦена` (число 15.2) | десятичное с запятой; у группы пусто | `85,00`; без пробелов, без знака валюты, без разделителя групп |
| 8 | `Валюта` | `Валюта` (`СправочникСсылка.Валюты`), через `Строка()` | строка; у группы пусто | представление валюты: `Российский рубль`, `Доллар США` |

Заголовок файла — ровно эта строка:

```
Код;Наименование;ЭтоГруппа;Родитель;ВидУслуги;Единица;БазоваяЦена;Валюта
```

### Правила экранирования

1. Поле **не** заключается в кавычки, если в нём нет `;`, `"`, перевода строки (LF) или возврата
   каретки (CR). Кавычки не украшение — они нужны только там, где без них строка не разберётся.
2. Поле **заключается** в двойные кавычки, если содержит разделитель `;`, двойную кавычку,
   LF или CR. Кавычки ставятся вокруг всего поля, а не вокруг проблемного фрагмента.
3. Внутренняя двойная кавычка удваивается: наименование `Номер "Deluxe"` пишется как
   `"Номер ""Deluxe"""`.
4. Открывающая кавычка распознаётся только в начале поля. Поэтому `;` внутри поля без кавычек
   не «проваливается», а сдвигает все последующие колонки — такой файл считается испорченным.
5. Перевод строки внутри поля допустим только в кавычках; тогда одна логическая запись занимает
   несколько физических строк файла, а разбор идёт по кавычкам, а не по строкам.
6. Обратное преобразование выполняет `СобратьСтроку`: она сама решает, нужно ли поле в кавычки,
   и удваивает внутренние кавычки. Ручная сборка строки в обход неё не допускается.

### Примеры

Позиция номенклатуры. В наименовании есть точка с запятой, поэтому поле взято в кавычки; пустых
полей нет, всего 8 значений:

```
000000017;"Виза ОАЭ; срочная";Ложь;Виза;Виза;Штука;9000,00;Российский рубль
```

Разбор этой строки даёт поля: `000000017` | `Виза ОАЭ; срочная` | `Ложь` | `Виза` | `Виза` |
`Штука` | `9000,00` | `Российский рубль`.

Группа. Обязательны только код, наименование и признак группы; четыре последних поля пустые:

```
000000006;Виза;Истина;;;;;
```

Разбор даёт 8 полей: `000000006` | `Виза` | `Истина` | пусто | пусто | пусто | пусто | пусто.

Оба примера дословно проверяются сценарием `selftest` драйвера `epf/ТестОбмена` (функция
`ПроверитьРазбор`): если парсер и этот раздел разойдутся, прогон даст `FAIL` и вердикт `FAIL`.
Поэтому при изменении формата правьте и примеры, и драйвер — иначе проверка станет ложной.

## Правила загрузки номенклатуры

Загружает `Обработки.ОбменСФайлами.ЗагрузитьНоменклатуру(ПутьФайла, Отчёт)`. Порядок проверок
в коде фиксирован и определяет, какое сообщение получит пользователь, если в строке несколько
разных дефектов.

### Порядок проверок

| № | Этап | Что проверяется | Метод |
|---|---|---|---|
| 1 | Заголовок | каждая обязательная колонка присутствует в первой строке файла | `ЗагрузитьНоменклатуру` |
| 2 | Лишние колонки | колонки заголовка вне списка обязательных не мешают, но попадают в отчёт предупреждением | `ЗагрузитьНоменклатуру` |
| 3 | Число полей | в строке данных не меньше полей, чем колонок в заголовке | `ЗагрузитьНоменклатуру` |
| 4 | Типы | `БазоваяЦена` приводится к числу, `ЭтоГруппа` — к булеву | `ПроверитьТипыСтроки` |
| 5 | Ссылки | `ВидУслуги`, `Единица`, `Валюта`, `Родитель` разрешаются в существующий объект | `ПроверитьСсылкиСтроки` |
| 6 | Уникальность | код не повторяется в файле и не занят в базе | `ПроверитьУникальностьКодов`, `ТекстНарушенияУникальности` |
| 7 | Правила записи | `ПравилаЗаписи` объекта не возвращает нарушений | `ЗаписатьЭлементНоменклатуры` |
| 8 | Запись | элемент пишется в транзакции и получает ссылку | `ЗаписатьЭлементНоменклатуры` |

Этапы 1–2 выполняются один раз на файл, этапы 3–8 — на каждую строку данных. Этапы 6–8 идут
после цикла разбора: уникальность проверяется одним запросом по всем кодам сразу, а строка,
отклонённая на этапах 3–5, в проверке уникальности не участвует и не может «занять» чужой код.

Порядок «типы → ссылки» не косметический: пока значение не приведено к своему типу, по нему
нечего искать, и сообщение должно указывать на значение, а не на несуществующий объект.

### Сообщения

Тексты ниже — дословно из `src/КурсоваяРабота/DataProcessors/ОбменСФайлами/Ext/ObjectModule.bsl`,

`<...>` — подстановка. `Строка 0` означает, что сообщение относится к файлу в целом, а не к записи.

| `Строка <N>, колонка "<Колонка>": "<значение>" неоднозначная ссылка, найдено <k> вариантов` | Ошибка | в справочнике больше одного объекта с таким наименованием; обмен не выбирает за человека |
| `Строка <N>, колонка "ВидУслуги": "<значение>" не найдено в перечислении "ВидыУслуг"` | Ошибка | нет значения перечисления ни с таким представлением, ни с таким именем |
| `Строка <N>, колонка "ВидУслуги": "<значение>" перечисление "ВидыУслуг" отсутствует в конфигурации` | Ошибка | ошибка конфигурации, а не данных: перечисления нет в метаданных. На рабочей базе не встречается |
| `Строка <N>: код "<код>" повторяется в строке <M>` | Ошибка | код встречается в файле несколько раз; выдаётся для первого вхождения и отсылает к следующему. Отклоняются **все** строки с этим кодом: какая из них верна, из файла не следует |
| `Строка <N>: код "<код>" уже встречался в строке <M>` | Ошибка | то же нарушение для остальных вхождений повторяющегося кода; отсылает к первому вхождению |
| `Строка <N>: код "<код>" неоднозначен, в базе <k> элементов` | Ошибка | в справочнике уже больше одного элемента с таким кодом (базу правила вручную или загрузили в обход); к какому из них относится строка — неизвестно |
| `Строка <N>: элемент с кодом "<код>" уже существует` | Ошибка | код уже занят в базе. Импорт создаёт элементы, но не обновляет существующие |
| `Строка <N>: Базовая цена не может быть отрицательной.` | Ошибка | нарушено правило записи справочника `НоменклатураУслуг`; текст берётся из `ПравилаЗаписи` и приходит с завершающей точкой |
| `Строка <N>: <ОписаниеОшибки()>` | Ошибка | платформа отказала в записи: исключение внутри транзакции, транзакция отменена. Текст описания платформенный и в этой документации не фиксируется |

Сообщения этапов 1–6 попадают в отчёт с номером строки файла (данные нумеруются с 1, заголовок
не считается), этапы 7–8 — тоже. Пустое значение ссылочной колонки не ищется: для `Родитель`
пустая строка означает верхний уровень, для остальных колонок — «не заполнено». Поэтому
незаполненная ссылка никогда не даёт ошибки разбора.

### Вердикты

`ВердиктОтчёта` считает вердикт только по счётчикам отчёта, а не по наличию строк в таблице
ошибок: предупреждение о лишней колонке вердикт не меняет.

| Вердикт | Условие |
|---|---|
| `PASS` | `ВсегоСтрок = 0` — файл без строк данных. Пустой файл не ошибка: загружать было нечего, отклонять тоже нечего |
| `PASS` | `Отклонено = 0` — все строки файла записаны |
| `FAIL` | `Загружено = 0` при `Отклонено > 0`: ни одна строка не записана, файл не подошёл целиком. Сюда же относится отказ по заголовку — там `FAIL` ставится явно, до обработки строк |
| `ЧАСТИЧНО` | `Загружено > 0` и `Отклонено > 0`: часть строк принята, часть отклонена |

Ту же функцию вызывает `ЗаписатьОтчёт`, поэтому последняя строка текстового отчёта — `ВЕРДИКТ:
<значение>` — не может разойтись с вердиктом структуры отчёта.

### Частичная загрузка

1. Две фазы: сначала разбирается и проверяется весь файл, потом пишутся принятые строки. Разбор
   в справочник не пишет ничего — до записи первого элемента уже известно, какие строки допустимы.
2. Каждая строка пишется в собственной транзакции (`НачатьТранзакцию` / `ЗафиксироватьТранзакцию`
   внутри `ЗаписатьЭлементНоменклатуры`): отказ по строке N не откатывает уже записанные
   строки 1…N−1.
3. Элемент пишется целиком, одним вызовом `Объект.Записать()`: полузаписанных элементов (только
   с кодом и наименованием) не остаётся. Отменённая транзакция отбрасывает элемент полностью.
4. Строка отклоняется целиком: частичного применения полей строки нет. Половина полей строки
   в справочник не попадает.
5. `ОбменДанными.Загрузка` не выставляется: элемент проходит те же проверки, что и введённый
   вручную. Поэтому `ПравилаЗаписи` вызываются заранее — иначе в отчёте осталось бы «Запись
   запрещена» без причины.
6. `Загружено` — число реально записанных элементов, а не число строк, прошедших разбор: отказ
   правил записи или платформы отклоняет строку.
7. Повторный прогон того же файла после успешной загрузки даст по каждой строке `элемент с кодом
   "<код>" уже существует`: импорт не обновляет, а создаёт.
8. Группы справочника загрузка не создаёт: `Родитель` ищется в базе, а не в файле, поэтому
   родительская группа должна быть заведена заранее. Порядок строк в файле на это не влияет.

### Ограничение текущей реализации

`ЭтоГруппа` из файла проходит только проверку типа и при записи не присваивается: в
`ЗаписатьЭлементНоменклатуры` реквизит `ЭтоГруппа` объекта не заполняется. Строка с `Истина`
создаст обычный элемент справочника, а не группу. Группы заводятся в базе заранее; из файла
их создание не поддерживается.

### Уборка тестовых объектов

Импорт не удаляет ничего: ни элементов, ни групп, ни ошибочных записей. Удаление тестовых
объектов — обязанность вызывающей стороны, то есть сценария проверки или человека, запускающего
прогон. Тестовые объекты (коды вида `999…`, наименования вида `ТЕСТ-…`) убираются до и после
прогона тем же драйвером `epf/ТестОбмена`: иначе повторный прогон даст `уже существует`,
а база после неудачной проверки останется грязной. Обработка `ОбменСФайлами` каталог не чистит
и «откат» выполненной загрузки не предоставляет.

## Формат заказов поставщику

Файл формирует `Обработки.ОбменСФайлами.ВыгрузитьЗаказы(ПутьФайла, ПериодС, ПериодПо)`, читает
обратно `ОбменCSV.ПрочитатьФайл(ПутьФайла)`. Состав и порядок колонок задаёт единственная функция
`КолонкиЗаказов()` из `DataProcessors/ОбменСФайлами/Ext/ObjectModule.bsl`: из неё же берётся
заголовок файла, поэтому заголовок и разбор не могут разойтись.

Общие свойства файла — кодировка UTF-8 с BOM, разделитель `;`, CRLF, десятичная запятая,
формат дат `ГГГГ-ММ-ДД`, правила экранирования — те же, что в разделе
«Формат номенклатуры услуг», и здесь не повторяются.

| 6 | `ДатаОжиданияПодтверждения` | `ЗаказПоставщику.ДатаОжиданияПодтверждения` | дата `ГГГГ-ММ-ДД` или пусто | реквизит шапки; незаполненная дата даёт пустое поле, а не `0001-01-01` |
| 7 | `Статус` | `ЗаказПоставщику.Статус` через `Строка()` | строка, может быть пустой | в файл идёт представление значения, по нему же значение находится при обратной загрузке |
| 8 | `Комментарий` | `ЗаказПоставщику.Комментарий` | многострочный текст, может быть пустым | свободный текст шапки; переводы строк и `;` допустимы — поле берётся в кавычки по общим правилам экранирования |
| 9 | `Ответственный` | `ЗаказПоставщику.Ответственный` через `Строка()` | строка, может быть пустой | представление пользователя |
| 10 | `Услуга` | `ЗаказПоставщику.Услуги.Услуга` через `Строка()` | строка | представление номенклатуры услуги; именно эта колонка делает строку файла строкой табличной части |
| 11 | `Объект` | `ЗаказПоставщику.Услуги.Объект` через `Строка()` | строка, может быть пустой | представление объекта услуги |
| 12 | `ДатаНачала` | `ЗаказПоставщику.Услуги.ДатаНачала` | дата `ГГГГ-ММ-ДД` | начало оказания услуги, а не дата документа |
| 13 | `ДатаОкончания` | `ЗаказПоставщику.Услуги.ДатаОкончания` | дата `ГГГГ-ММ-ДД` | окончание оказания услуги |
| 14 | `Количество` | `ЗаказПоставщику.Услуги.Количество` через `ОбменCSV.СформироватьЧисло()` | десятичное с запятой, два знака | `7,00`, не `7` и не `7,0` |
| 15 | `ТипНомера` | `ЗаказПоставщику.Услуги.ТипНомера` через `Строка()` | строка, может быть пустой | представление значения; пусто у услуг, для которых тип номера не задаётся |
| 16 | `ТипПитания` | `ЗаказПоставщику.Услуги.ТипПитания` через `Строка()` | строка, может быть пустой | представление значения; пусто у услуг, для которых тип питания не задаётся |
| 17 | `Цена` | `ЗаказПоставщику.Услуги.Цена` через `ОбменCSV.СформироватьЧисло()` | десятичное с запятой, два знака | цена за единицу строки табличной части |
| 18 | `Сумма` | `ЗаказПоставщику.Услуги.Сумма` через `ОбменCSV.СформироватьЧисло()` | десятичное с запятой, два знака | сумма строки табличной части, а не итог документа |
| 19 | `ДополнительныеПараметры` | `ЗаказПоставщику.Услуги.ДополнительныеПараметры` через `Строка()` | строка, может быть пустой | свободное представление; при загрузке в документ не раскладывается |

Заголовок файла — ровно эта строка (19 имён через `;`):

```
Номер;Дата;ЗаявкаНаТур;Поставщик;Договор;ДатаОжиданияПодтверждения;Статус;Комментарий;Ответственный;Услуга;Объект;ДатаНачала;ДатаОкончания;Количество;ТипНомера;ТипПитания;Цена;Сумма;ДополнительныеПараметры
```

### СуммаДокумента не выгружается

Итог документа (`СуммаДокумента`) в файл **не пишется**. Причина: он вычисляется по строкам услуги,
и в файле он был бы вторым, независимым источником того же числа — разошлись бы ровно там, где
в файле ошиблись в одной сумме, и было бы неизвестно, какому из двух чисел верить.

При загрузке итог **пересчитывается** по загруженным строкам. Поэтому в файле обязательны
корректные `Количество`, `Цена` и `Сумма` по каждой строке, а итога документа среди колонок
не ищите: его там нет и не будет.

### Правила структуры файла

1. **Одна строка файла — одна строка табличной части «Услуги».** Отдельной строки «шапка документа»
   без услуги в файле нет: строка без услуги данных не несёт.
2. **Реквизиты шапки повторяются в каждой строке своего документа** — колонки 1–9 дословно совпадают
   у всех строк одного заказа. Файл плоский, и восстановить принадлежность строки документу иначе
   было бы нечем. Расхождение в этих колонках внутри одной группы строк означает испорченный файл,
   а не два документа.
3. **Строки файла упорядочены**: по номеру документа, внутри документа — по номеру строки
   табличной части. Порядка строк достаточно, чтобы читать файл построчно, но принадлежность
   строки всё равно определяется по шапке, а не по соседству.
4. **Заказ без строк услуги в файл не попадает**: выборка идёт внутренним соединением шапки
   с табличной частью. Пустой заказ с точки зрения обмена не содержит данных.
5. **Заголовок обязателен и содержит ровно 19 колонок.** Колонки читаются по именам: лишняя колонка
   не ломает разбор, но её значения не читаются. Перестановка колонок допустима только вместе
   с заголовком.
6. **Число полей в строке данных равно числу колонок заголовка.** Пустое значение — пустое поле
   между разделителями: `;;`. Число полей не сокращается пропуском хвостовых значений: последняя
   колонка `ДополнительныеПараметры` остаётся в строке даже пустой (строка заканчивается `;`).
7. **Ключ документа — `Номер` + `Дата`**: оба реквизита повторяются в каждой строке, и только вместе
   они определяют документ однозначно. Ни номер, ни дата по отдельности ключом не являются.

### Пример: два строки одного документа

Документ `ЗП-00000001` от `2026-10-21` с двумя строками услуги. В комментарии шапки есть `;`
и двойные кавычки, поэтому поле взято в кавычки, а внутренние кавычки удвоены; в первой строке
услуги совпадают все девять колонок шапки, во второй — те же девять значений и другая услуга:

```
ЗП-00000001;2026-10-21;ЗТ-000012;ООО Ривьера;ДГ-000045;2026-10-25;Подтвержден;"Номер ""Deluxe""; вид на море";Иванов Иван Иванович;Номер Deluxe;Отель Ривьера;2026-11-01;2026-11-08;7,00;Deluxe;Завтрак;9000,00;63000,00;
ЗП-00000001;2026-10-21;ЗТ-000012;ООО Ривьера;ДГ-000045;2026-10-25;Подтвержден;"Номер ""Deluxe""; вид на море";Иванов Иван Иванович;Завтрак;Отель Ривьера;2026-11-01;2026-11-08;14,00;;Завтрак;1200,00;16800,00;
```

Разбор первой строки даёт 19 полей: `ЗП-00000001` | `2026-10-21` | `ЗТ-000012` | `ООО Ривьера` |
`ДГ-000045` | `2026-10-25` | `Подтвержден` | `Номер "Deluxe"; вид на море` | `Иванов Иван Иванович` |
`Номер Deluxe` | `Отель Ривьера` | `2026-11-01` | `2026-11-08` | `7,00` | `Deluxe` | `Завтрак` |
`9000,00` | `63000,00` | пусто.

Разбор второй строки отличается тремя полями: `Завтрак` | `Отель Ривьера` | `14,00` | пусто
(`ТипНомера`) | `Завтрак` | `1200,00` | `16800,00` | пусто. Все девять колонок шапки у обеих строк
совпадают — это и есть признак одного документа.

Итог документа в файле отсутствует: `63000,00 + 16800,00` — уже вычисленная величина, при загрузке
она получится сама.

## Правила загрузки заказов

Загружает `Обработки.ОбменСФайлами.ЗагрузитьЗаказы(ПутьФайла, Отчёт)`. Разбор устроен иначе, чем у
номенклатуры: файл плоский, поэтому сначала проверяется каждая строка, затем строки собираются в
документы, и только потом документ пишется. Единица учёта — **документ**, а не строка файла:
`Загружено` и `Отклонено` считают документы, `ВсегоСтрок` — строки файла.

### Порядок проверок

Порядок в коде фиксирован и определяет, какое сообщение получит пользователь, если в строке
несколько разных дефектов. Проверки одной строки идут накопительно: `ПроверитьСтрокуЗаказа`
возвращает массив, и в отчёт попадают все найденные дефекты этой строки, а не первый.

| № | Этап | Что проверяется | Метод |
|---|---|---|---|
| 1 | Заголовок | все 19 колонок из `КолонкиЗаказов()` присутствуют в первой строке файла | `ПроверитьЗаголовокЗаказа` |
| 2 | Лишние колонки | колонки заголовка вне списка обязательных не мешают, но попадают в отчёт предупреждением | `ПроверитьЗаголовокЗаказа` |
| 3 | Число полей | в строке данных не меньше полей, чем колонок в заголовке | `ЗагрузитьЗаказы` |
| 4 | Ключ строки | `Номер` не пуст; `Дата` заполнена и приводится к дате | `ПроверитьСтрокуЗаказа` |
| 5 | Остальные даты | `ДатаОжиданияПодтверждения`, `ДатаНачала`, `ДатаОкончания`: пусто допустимо, непустое значение обязано приводиться к дате | `ДобавитьОшибкуДаты` |
| 6 | Числа | `Количество`, `Цена` приводятся к числу | `ДобавитьОшибкуТипа` |
| 7 | Ссылки | `Статус` (перечисление `СтатусыЗаказа`), `ЗаявкаНаТур`, `Поставщик`, `Договор`, `Ответственный`, `Услуга`, `Объект` разрешаются в существующий объект | `ПроверитьСтрокуЗаказа` |
| 8 | Конфликт дат | один `Номер` не встречается в файле с разными `Дата` | `НомераСРазнымиДатами` |
| 9 | Группировка | строки собираются в документы по ключу `Номер` + `Дата` | `СгруппироватьСтрокиЗаказов` |
| 10 | Отчёт по документам | документ, у которого есть отклонённая строка, не пишется целиком и получает одну запись в отчёте | `СообщитьОбОшибочныхДокументах`, `СообщитьОКонфликтахДат` |
| 11 | Сборка документа | поставщик → договор → ответственный, статус, дата ожидания, комментарий → строки услуги → `СуммаДокумента` | `ЗаписатьДокументЗаказа` |
| 12 | Правила записи | `ПравилаЗаписи` документа не возвращает нарушений — **до** транзакции | `ЗаписатьДокументЗаказа` |
| 13 | Запись | `Записать()` в транзакции, затем проверка заполнения `Ссылка` | `ЗаписатьДокументЗаказа` |

Этапы 1–2 выполняются один раз на файл, этапы 3–7 — на каждую строку данных, этапы 8–13 — на
каждый документ. Колонка `Сумма` не проверяется вообще: её значение из файла не читается, поэтому и
дефект в ней дефектом не считается (см. «Пересчёт сумм»).

### Ключ группировки и что с ним связано

1. **Ключ документа — `Номер` + `Дата`**, в коде это строка `"<Номер>|<ГГГГ-ММ-ДД>"`. Ни номер, ни
   дата по отдельности документ не определяют: номер документа уникален только внутри года.
2. **Строка без номера или без читаемой даты в группировку не попадает.** Она уже отклонена на
   этапах 4–5, и её номер документа запоминается отдельно — чтобы отклонить документ, к которому она
   относилась.
3. **Один `Номер` с разными `Дата` отклоняется целиком.** Какой из дат верить, из файла не следует, а
   два документа с одним номером записать нельзя. В сообщение попадает только первое расхождение:
   третья дата ничего не меняет.
4. **Шапка документа берётся из первой строки группы.** Файл плоский, и все строки документа несут
   одну и ту же шапку; различие колонок 1–9 внутри группы — признак испорченного файла, а не повод
   выбрать одну из шапок. Загрузка такое различие не диагностирует отдельным сообщением: пишется
   шапка первой строки.
5. **Документ, у которого хотя бы одна строка отклонена, не пишется целиком.** Записать его без
   части услуг значило бы молча потерять данные.
6. **`Отклонено` считает документы, а не строки**: у документа с тремя ошибочными строками одна
   запись в отчёте и один отклонённый документ.
7. **Строки с пустым `Номер` собираются в одну группу** (ключ — пустая строка) и дают одно сообщение
   `Документ не записан: в строке <первая> не прочитан номер документа`: отнести их к разным
   документам нечем.

### Сообщения

Тексты ниже — дословно из `src/КурсоваяРабота/DataProcessors/ОбменСФайлами/Ext/ObjectModule.bsl`.
`<...>` — подстановка. «Строка 0» означает, что сообщение относится к файлу в целом, а не к записи.
В поле «Объект» отчёта у сообщений о документе стоит номер документа, у сообщений о строке — пусто,
а номер строки файла уже входит в текст (данные нумеруются с 1, заголовок не считается).

**Файл в целом**

| Текст сообщения | Уровень | Когда возникает |
|---|---|---|
| `Отсутствует обязательная колонка "<Колонка>"` | Ошибка | в заголовке нет обязательной колонки; по одной на каждую недостающую. Строки не обрабатываются, вердикт сразу `FAIL`, документы не пишутся |
| `Колонка "<Колонка>" проигнорирована` | Предупреждение | в заголовке есть колонка вне списка обязательных; её значения не читаются, остальное обрабатывается как обычно |

**Строка файла**

| Текст сообщения | Уровень | Когда возникает |
|---|---|---|
| `Строка <N>: ожидалось <K> полей, получено <M>` | Ошибка | в строке меньше полей, чем колонок в заголовке. `K` — число колонок заголовка, а не константа 19: лишняя колонка увеличивает и ожидание. Строка отклоняется |
| `Строка <N>, колонка "Номер": номер документа не заполнен` | Ошибка | пустой `Номер`. Строку не к чему отнести, документ отклоняется |
| `Строка <N>, колонка "Дата": не заполнено обязательное значение` | Ошибка | пустая `Дата` документа |
| `Строка <N>, колонка "<Колонка>": не удалось привести к дате, получено "<значение>"` | Ошибка | колонка из `Дата`, `ДатаОжиданияПодтверждения`, `ДатаНачала`, `ДатаОкончания` не разбирается как дата `ГГГГ-ММ-ДД` |
| `Строка <N>, колонка "<Колонка>": не удалось привести к числу, получено "<значение>"` | Ошибка | колонка `Количество` или `Цена` не разбирается как число по правилам раздела «Формат номенклатуры услуг»: десятичная запятая, без пробелов и разделителей групп. Колонка `Сумма` этой проверки не проходит — она не читается |
| `Строка <N>, колонка "Статус": "<значение>" не найдено в перечислении "СтатусыЗаказа"` | Ошибка | нет значения перечисления ни с таким представлением, ни с таким именем |
| `Строка <N>, колонка "Статус": "<значение>" перечисление "СтатусыЗаказа" отсутствует в конфигурации` | Ошибка | ошибка конфигурации, а не данных. На рабочей базе не встречается |
| `Строка <N>, колонка "<Колонка>": "<значение>" не найдено в справочнике "<Имя>"` | Ошибка | ссылка не разрешилась. Колонка и справочник: `ЗаявкаНаТур` → `ЗаявкиНаТур`, `Поставщик` → `Поставщики`, `Договор` → `ДоговорыСПоставщиками`, `Ответственный` → `Сотрудники`, `Услуга` → `НоменклатураУслуг`, `Объект` → `ОбъектыГостеприимства` |
| `Строка <N>, колонка "<Колонка>": "<значение>" неоднозначная ссылка, найдено <k> вариантов` | Ошибка | в справочнике больше одного объекта с таким наименованием; обмен не выбирает за человека |

Пустая ячейка ссылочной колонки не ищется и ошибки не даёт: «не заполнено» — допустимое состояние
для всех ссылочных колонок этого файла. Но документ без `Услуга` не собирается: строка без услуги
данных не несёт, и отказ по ней приходит уже как сообщение по документу.

**Документ**

| Текст сообщения | Уровень | Когда возникает |
|---|---|---|
| `Документ не записан: в строке <N> не прочитан номер документа` | Ошибка | у отклонённых строк не удалось прочитать `Номер`; сообщение одно на все такие строки |
| `Документ "<Номер>" не записан: в файле <k> ошибочных строк` | Ошибка | у документа есть отклонённые строки. Сообщение выдаётся на номер документа один раз и не повторяется при записи |
| `Номер "<Номер>" встречается с разными датами (<Первая> и <Вторая>)` | Ошибка | один номер в файле с разными `Дата`; номер отклоняется целиком |
| `Документ "<Номер>" не записан, строка <N>, колонка "Поставщик": "<значение>" не найдено в справочнике "Поставщики"` | Ошибка | поставщик указан текстом, но в базе не найден. Документ отклоняется до сборки строк |
| `Документ "<Номер>" не записан, строка <N>, колонка "Договор": <причина>` | Ошибка | договор не разрешился в пределах поставщика заказа. `<причина>` — один из текстов: `не найдено в справочнике "ДоговорыСПоставщиками"`, `неоднозначная ссылка, найдено <k> вариантов`, `Договор "<значение>" принадлежит другому поставщику`, `Договор "<значение>" не найден: не указан поставщик` |
| `Документ "<Номер>" не записан, строка <N>, колонка "Услуга": "<значение>" не найдено в справочнике "НоменклатураУслуг"` | Ошибка | услуга указана текстом, но в справочнике не найдена. Документ отклоняется целиком |
| `Документ "<Номер>" не записан, строка <N>, колонка "Объект": <причина>` | Ошибка | объект не разрешился в пределах поставщика заказа. `<причина>` — те же четыре текста, что и у договора, с понятием `Объект` и справочником `ОбъектыГостеприимства` |
| `Документ "<Номер>" не записан: <нарушение>` | Ошибка | нарушено правило записи документа `ЗаказПоставщику`; по сообщению на каждое нарушение. Текст берётся из `ПравилаЗаписи` |
| `Документ "<Номер>" не записан: <ОписаниеОшибки()>` | Ошибка | платформа отказала в записи: исключение внутри транзакции, транзакция отменена. Сюда же попадает `Запись отклонена правилами объекта` — случай, когда `Записать()` прошёл, но `Ссылка` осталась пустой. Текст описания платформенный и в этой документации не фиксируется |

### Пересчёт сумм

`Сумма` строки и `СуммаДокумента` — вычисляемые величины, значения из файла игнорируются полностью.

1. **`Сумма` строки** считается по `Количеству` и `Цене`:
   `РасчётКомпенсаций.РассчитатьСуммуСтроки(КоличествоУслуги, ЦенаУслуги)`. Колонка `Сумма` файла
   не читается и не сверяется — расхождение в ней не диагностируется.
2. **`СуммаДокумента`** считается по уже собранным строкам:
   `РасчётКомпенсаций.СуммаТабличнойЧасти(Объект.Услуги)`. Итога в файле нет (см. «СуммаДокумента
   не выгружается»), поэтому второго источника того же числа не возникает.
3. **Источник истины один — `Количество` и `Цена`.** Поэтому в файле обязательны корректные значения
   именно этих колонок: ошибка в них отклоняет строку, а значение `Сумма` не значит ничего.
4. **Документ не проводится.** `Записать()` вызывается без режима проведения: проведение требует
   данных, которых в файле нет, и частично проведённый заказ хуже непроведённого.

### Атомарность записи документа

1. **Правила записи проверяются до транзакции**: `Объект.ПравилаЗаписи(Объект)` вызывается на
   полностью собранном объекте. Отказ попадает в отчёт с номером документа, а не превращается в
   молчаливую пустую ссылку: `ПередЗаписью` не сообщает, какое правило нарушено.
2. **Транзакция — на один документ**: `НачатьТранзакцию()` → `Записать()` → проверка →
   `ЗафиксироватьТранзакцию()`, при исключении — `ОтменитьТранзакцию()`. Отказ по документу N не
   откатывает уже записанные документы.
3. **После `Записать()` проверяется `ЗначениеЗаполнено(Объект.Ссылка)`.** Отказ в `ПередЗаписью` не
   бросает исключение — платформа просто оставляет ссылку пустой; без этой проверки отчёт объявил бы
   документ записанным. Пустая ссылка превращается в исключение и откат транзакции.
4. **Документ пишется целиком или не пишется вовсе**: полузаписанного заказа (только шапка, без
   услуг) не остаётся, отменённая транзакция отбрасывает объект полностью.
5. **`ОбменДанными.Загрузка` не выставляется**: документ проходит те же проверки, что и введённый
   вручную. Именно поэтому `ПравилаЗаписи` вызываются заранее — иначе в отчёте осталось бы «Запись
   запрещена» без причины.
6. **`Загружено` — число реально записанных документов**, а не число собранных: отказ правил записи,
   отказ разрешения ссылки или отказ платформы отклоняет документ.

### Сужение поиска по поставщику

`Поставщик` разрешается первым: с него начинается сборка документа, и без него сузить поиск нечем.

1. **Без поставщика искать нечего.** Если текст `Поставщик` не пуст, а в справочнике его нет,
   документ отклоняется сразу с сообщением о колонке `Поставщик`, до сборки строк. Молча оставить
   реквизит пустым значило бы отдать причину отказа правилам записи документа.
2. **`Договор` ищется только среди договоров выбранного поставщика**
   (`НайтиДоговорПоставщика` → `НайтиОбъектВладельца`). Одноимённый договор другого поставщика
   этому заказу не принадлежит.
3. **`Объект` ищется только среди объектов выбранного поставщика** (`НайтиОбъектПоставщика`) — по
   тому же правилу: чужой объект сделал бы строку противоречивой.
4. **Чужой владелец — отдельное сообщение, а не «не найдено».** Найденный у другого владельца
   договор (или объект) даёт `принадлежит другому поставщику`: файл ссылается на существующую
   запись, и человеку нужно сказать именно об этом. Отсутствие записи даёт
   `не найдено в справочнике "<Имя>"`.
5. **Если поставщик не указан вообще**, а `Договор` или `Объект` заполнены, сообщение —
   `<Понятие> "<значение>" не найден: не указан поставщик`: сравнение с пустым владельцем нашло бы
   только осиротевшие записи и выдало бы чужой договор за свой.
6. **Неоднозначность решается отказом.** Если у одного поставщика два договора (или объекта) с
   одинаковым наименованием, выдаётся `неоднозначная ссылка, найдено <k> вариантов`: угадывание было
   бы хуже ошибки.
7. **`ЗаявкаНаТур`, `Ответственный`, `Услуга` сужению не подлежат** — у этих справочников нет
   владельца-поставщика, и они ищутся по всему справочнику.

Ограничение, о котором стоит знать: на этапе 7 (разбор строки) `Договор` и `Объект` проверяются
общим поиском по наименованию, без учёта владельца, — сужение по поставщику происходит на этапе 11,
при сборке документа. Поэтому договор, у которого есть тёзка у другого поставщика, отклоняется на
этапе 7 как `неоднозначная ссылка`, хотя сам по себе он корректен. Однозначное наименование
проходит оба этапа.

### Счётчики и вердикты

`ВердиктОтчёта` считает вердикт только по счётчикам отчёта, а не по наличию строк в таблице ошибок:
предупреждение о лишней колонке вердикт не меняет.

| Вердикт | Условие |
|---|---|
| `PASS` | `ВсегоСтрок = 0` — файл без строк данных. Пустой файл не ошибка: загружать было нечего, документов записано 0 |
| `PASS` | `Отклонено = 0` — все документы файла записаны |
| `FAIL` | `Загружено = 0` при `Отклонено > 0`: ни один документ не записан, файл не подошёл целиком. Сюда же относится отказ по заголовку — там `FAIL` ставится явно, до обработки строк |
| `ЧАСТИЧНО` | `Загружено > 0` и `Отклонено > 0`: часть документов записана, часть отклонена |

Единицы счётчиков разные, и это не опечатка: `ВсегоСтрок` — строки файла, `Загружено` и
`Отклонено` — документы. Файл из трёх строк одного заказа, записанного успешно, даёт
`ВсегоСтрок = 3`, `Загружено = 1`, `Отклонено = 0`.

Ту же функцию вызывает `ЗаписатьОтчёт`, поэтому последняя строка текстового отчёта — `ВЕРДИКТ:
<значение>` — не может разойтись с вердиктом структуры отчёта.

Номер, у которого есть и отклонённые строки, и конфликт дат, даёт две ошибки и увеличивает
`Отклонено` дважды: `НомераСОшибками` и `КонфликтыДат` учитываются независимо. На вердикт это не
влияет (он считается по «есть ли хоть один записанный документ»), но счётчик отклонённых в этом
случае больше числа документов.
