## 2. Как подключено (технически)

**Файловая структура:**
- верхний уровень: `src/КурсоваяРабота/Subsystems/<Имя>.xml`;
- вложенные разделы: `src/КурсоваяРабота/Subsystems/<Родитель>/Subsystems/<Раздел>.xml`.

**Регистрация:**
- 7 верхних подсистем зарегистрированы в `src/КурсоваяРабота/Configuration.xml` — элементы `<Subsystem>` в `ChildObjects` (проверено: ровно 7);
- каждый раздел зарегистрирован в `ChildObjects/Subsystem` своего родителя, например у `ОператорСопровождения.xml`:
  ```xml
  <ChildObjects>
      <Subsystem>ЗаказыПоставщикам</Subsystem>
      <Subsystem>ЗапросыТуристов</Subsystem>
      <Subsystem>МоиЗаявки</Subsystem>
      <Subsystem>Подтверждения</Subsystem>
  </ChildObjects>
  ```

**Состав объектов** — в `Properties/Content` подсистемы, элемент типа `xr:MDObjectRef`, например:
```xml
<Content>
    <xr:Item xsi:type="xr:MDObjectRef">Catalog.ЗаявкиНаТур</xr:Item>
</Content>
```

**Свойства подсистем:** `IncludeInCommandInterface = true` (разделы видны в командном интерфейсе), `UseOneCommand = false`, `IncludeHelpInContents = true`, синоним и пояснение (explanation) заданы по ТЗ. Каждая подсистема получила собственный UUID.

**Где посмотреть:**
- Конфигуратор: «Общие → Подсистемы» (дерево), у каждой — вкладки «Состав» и «Командный интерфейс»;
- в интерфейсе 1С — панель разделов (после загрузки конфигурации в информационную базу; загрузка в объём задачи не входила).

## 6. Принятые решения и отклонения от основного ТЗ

1. Структура выбрана **по рабочим местам** из Дополнения (раздел 6), а не по типам объектов из основного ТЗ («Справочники», «Документы», …) — по решению заказчика. При необходимости типовые подсистемы можно добавить позже.
2. Регистры и перечисления включены в разделы рабочих мест и «Сервис», хотя в основном ТЗ для них предполагались отдельные подсистемы — иначе 31 объект остался бы вне подсистем.
3. Служебные объекты (константа, ПВХ, задача, регистр адресации) вынесены в подсистему «Сервис».
4. Разделы без существующих объектов не создавались (перечислены в п. 4).
