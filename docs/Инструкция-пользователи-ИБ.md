# Инструкция: создание пользователей ИБ для проверки ролей (изменение add-access-roles)

Назначение: в файловой ИБ `db\КурсоваяРабота` нужно создать 7 платформенных
пользователей «Пользователи информационной базы» и каждому назначить ровно
одну роль. Это единственный шаг доработки, который делается руками (в
конфигураторе); всё остальное — публикация, сценарные проверки, отчёт —
выполняется автоматически после завершения инструкции.

## 0. Подготовка

- Закройте все сеансы 1С (и конфигуратор, и предприятие). Лицензия у нас
  локальная на одного пользователя — одновременных сеансов быть не должно.
  Проверка при желании: Диспетчер задач → процесс `1cv8.exe` должен отсутствовать.
- Запустите конфигуратор для нашей базы одним из способов:
  - обычный: окно запуска 1С → база «КурсоваяРабота» → **Конфигуратор**
    (платформа `C:\Program Files (x86)\1cv8\8.3.27.1786\bin`);
  - или строка запуска:
    `"C:\Program Files (x86)\1cv8\8.3.27.1786\bin\1cv8.exe" /F "D:\Projects\1C_prj\7 семестр\Kursovaya\db\КурсоваяРабота" /U Администратор /CONFIGURATOR`

## 1. Диалог пользователей

В конфигураторе: меню **Администрирование → Пользователи информационной базы…**

## 2. Список пользователей

Для каждой строки: кнопка **Добавить**, ввести **имя учётной записи** (логин —
ровно как в таблице, регистр и `_` важны, это имя для запуска) и **полное имя**,
затем в списке ролей отметить **ровно одну** роль галочкой. Никаких дополнительных
пользовательских настроек не требуется.

| № | Логин (имя пользователя ИБ) | Полное имя | Роль (единственная галочка) |
|---|---|---|---|
| 1 | `test_operator` | Оператор Сопровождения (тест) | `Профиль_Оператор` |
| 2 | `test_koordinator` | Координатор Логистики (тест) | `Профиль_Координатор` |
| 3 | `test_gid` | Гид На Маршруте (тест) | `Профиль_Гид` |
| 4 | `test_menuver` | Менеджер По Претензиям (тест) | `Профиль_МенеджерПретензий` |
| 5 | `test_rukovoditel` | Руководитель Направления (тест) | `Профиль_Руководитель` |
| 6 | `test_auditor` | Аудитор (тест) | `Профиль_Аудитор` |
| 7 | `test_admin` | Администратор ИС (тест) | `Администратор` |

Важно:
- роль у каждого пользователя строго одна — иначе сценарии «не видит чужой
  раздел» потеряют смысл;
- существующего пользователя `Администратор` не удалять и ему роли не менять;
- если диалог предлагает поле «Пароль»/флаги «Разрешить конфигуратор» — пароль
  не задавать, доступ в конфигуратор тестовым не давать (запуск предприятия
  разрешить всем).

## 3. Сохранение и завершение

1. После седьмого пользователя — **ОК** / закрыть диалог (список должен
   сохраниться; ошибки «не сохранено» быть не должно).
2. Если в диалоге/свойствах есть флаг «Требовать авторизацию пользователей ИБ» —
   его включать не нужно: имена задаём параметром запуска, пароли не используем.
3. Закрыть конфигуратор (сеанс 1С завершить полностью).

## 4. Что делать после

Написать «готово» — дальше я: проверю, что список пользователей виден платформе;
свяжу тестовых с записями справочника `Пользователи`/`Сотрудники` (это уже данные,
кодом); опубликую базу через Apache и прогоню сценарную батарею проверки прав
(видимость разделов, создание/запрет изменения, проведение, чтение регистров)
каждым из профилей; результат — в отчёте и артефактах изменения.

Время операции по факту: 5–7 минут. Если на каком-то шаге диалог выглядит не
так, как описано (другие кнопки/поля) — написать, как видит, подстроимся.
