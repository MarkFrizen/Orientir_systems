# Отчёт по тестированию типовых и граничных сценариев

Документ закрывает Задание 2: прогон типовых сценариев из `docs/Сценарии-работы-пользователей.md`, фиксация результатов (успех, обработанные ошибки, частичный успех), примеры сообщений пользователю и подтверждающие скриншоты.

Статус: **каркас, заполняется по ходу прогона**. Колонки «Факт», «Вердикт» и «Кадр» пустые намеренно.

---

## 1. Условия прогона

| Параметр | Значение |
|---|---|
| Дата прогона | заполнить |
| Конфигурация | «КурсоваяРабота», `src\КурсоваяРабота` |
| Информационная база | файловая, `db\КурсоваяРабота` |
| Платформа | 1С:Предприятие 8.3 (версия — заполнить) |
| Пользователь | заполнить (Администратор / профиль) |
| Состояние базы | демо-набор от 18.10.2026, наполнение `epf/run-fill.ps1` |
| Проверка целостности до прогона | `epf/run-check.ps1` → вердикт заполнить |

## 4. Ручной прогон типовых сценариев

Обозначения вердикта: `PASS` — сценарий отработал как описано; `PASS (ручной шаг)` — автоматика сработала, но часть шага выполняется вручную; `ЧАСТИЧНО` — поведение отличается от ожидаемого (фиксируется в разделе 7); `FAIL` — сценарий не выполняется.

| № | Сценарий | Шаги прогона | Ожидание | Факт | Вердикт | Кадр |
|---|---|---|---|---|---|---|
| 1 | С-01 Запросы поставщикам | раздел оператора → обработка «Формирование запросов поставщикам» → «Выполнить» | созданы заказы, статус `Отправлен`, повторный запуск без дублей | | | 06 |

## 5. Граничные кейсы

Выполняются после основного прогона: часть требует данных, которых нет в демо-наборе. После проверки данные убираются, чтобы не ломать снимок `expected-snapshot.json`.

| № | Кейс | Подготовка | Ожидание | Факт | Вердикт |
|---|---|---|---|---|---|
| Г-1 | Объект без часовой зоны | у объекта гостеприимства очистить `ЧасоваяЗона` | местное время не рассчитывается, сообщается название объекта и значение зоны | | |
| Г-2 | Поставщик без действующего договора | у договора поставить дату окончания в прошлое | заказ не создаётся, сообщение «не найден действующий договор поставщика» | | |
| Г-3 | Услуга без норматива срока | удалить запись из «Сроки контроля» по виду услуги | позиция не считается просроченной (**сообщения нет — дефект**) | | |
| Г-4 | Некорректный норматив SLA | в типе запроса указать `SLAЧасов = 0` | запись справочника отклоняется с сообщением о положительном нормативе | | |
| Г-5 | Дата инцидента в будущем | создать инцидент с датой завтра | отказ записи | | |
| Г-6 | Взыскание больше требования | в акте указать взыскание больше суммы претензии | отказ записи с указанием обеих сумм | | |
| Г-7 | Сумма строк не равна итогу | изменить сумму строки заказа | отказ записи с указанием обоих чисел | | |
| Г-8 | Частичный импорт CSV | загрузить `tests/exchange/fixtures/nomenclature-partial.csv` | вердикт `ЧАСТИЧНО`, часть строк отклонена с причинами | | |

Примечание: Г-4…Г-8 частично покрыты автотестами (`errors-dates`, `errors-amounts`, `import-nomenclature-partial`); ручной прогон нужен для скриншота и для проверки текста сообщения.

## 6. Частичный успех

| Механизм | Что происходит | Как проверить | Факт | Вердикт |
|---|---|---|---|---|
| Частичный импорт CSV | часть строк записана, часть отклонена с причинами, вердикт `ЧАСТИЧНО` | загрузка `nomenclature-partial.csv`, `nomenclature-bad-types.csv`, `nomenclature-missing-ref.csv` | | |
| Частичное подтверждение услуг | подтверждена часть услуг заказа — заявка остаётся `ВРаботе`, переходит в `Подтверждена` только при полном подтверждении | подтвердить одну услугу из нескольких | | |
| Пропуск позиций без норматива | позиция молча выпадает из контроля просрочек | Г-3 | | |

## 10. Выводы

Заполняется после прогона:

- сколько сценариев прошло полностью, сколько с ручным шагом, сколько частично, сколько не выполнено;
- какие требования ТЗ подтверждены фактически;
- какие расхождения зафиксированы и куда перенесены (`docs/Оставшиеся-задачи.md`, раздел «Задачи по ревизии сценариев»).

## 11. Приложение. Как воспроизвести

```powershell
# 0. Закрыть все сеансы 1С (лицензия на 1 место)
# 1. Наполнение и проверка демо-набора
powershell -ExecutionPolicy Bypass -File epf/run-fill.ps1
powershell -ExecutionPolicy Bypass -File epf/run-check.ps1

# 2. Автотесты с сохранением логов
New-Item -ItemType Directory -Force build/logs | Out-Null
powershell -ExecutionPolicy Bypass -File tests/posting/run-posting-tests.ps1 2>&1 | Tee-Object build/logs/posting-20261028.log
powershell -ExecutionPolicy Bypass -File tests/exchange/run-exchange-tests.ps1 2>&1 | Tee-Object build/logs/exchange-20261028.log
powershell -ExecutionPolicy Bypass -File tests/vanessa/run-xdd-smoke.ps1 2>&1 | Tee-Object build/logs/smoke-20261028.log

# 3. Ручной прогон по разделу 4 этого отчёта + съёмка кадров по docs/screenshots/README.md
```
