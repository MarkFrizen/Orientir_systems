# Чек-лист проверки расчётов и правил записи

Проверка того, что вошло в изменение `form-calculations-and-shared-modules`.

**Как читать шаг.** Каждый шаг — это сценарий: что открыть, что ввести, куда нажать, что должно появиться. Формат:

> **Действия** → **Ожидается** → **Если не так**

Сообщения приведены дословно, как их печатает код. Если текст отличается хотя бы одним словом — это дефект, записывай номер шага и фактический текст.

## Перед началом

- [ ] **П.1 Запуск базы**
  1. Закрыть все окна 1С (лицензия на одно место, иначе следующий запуск не откроется).
  2. Запустить `db/КурсоваяРабота`, пользователь `Администратор`, пароль пустой.
  3. Открыть раздел «Справочники НСИ».
  **Ожидается:** база открывается без предупреждений о несоответствии конфигурации.
  **Если не так:** значит, конфигурация БД не обновлена — прогнать `db-load-xml -UpdateDb` и повторить.

- [ ] **П.2 Порог согласования**
  1. Открыть константу `ПорогСогласованияРуководителем` (раздел администратора).
  **Ожидается:** значение 50 000.
  **Если 0:** любая претензия с положительной суммой потребует согласования, шаги раздела `ПретензияПоставщику` будут давать отказ на ровном месте. Поставить 50 000 и записать.

- [ ] **П.3 Наполнение**
  1. Открыть журналы: «Поставщики», «Договоры с поставщиками», «Объекты гостеприимства», «Номенклатура услуг», «Туристы».
  **Ожидается:** 18, 18, 15, 15, 20 записей соответственно.
  **Если меньше:** база не наполнена — прогнать `epf/run-fill.ps1` и вернуться к проверке.

- [ ] **П.4 Итог документа только для чтения**
  1. Открыть любой заказ поставщику.
  2. Кликнуть в поле «Сумма документа» в шапке и попробовать ввести символ.
  **Ожидается:** поле не принимает ввод, курсор остаётся, значение не меняется.
  **Если редактируется:** снят признак «Только просмотр» у элемента формы — дефект формы.

- [ ] **П.5 Подготовка договора для расчёта компенсации**
  1. В справочнике «Договоры с поставщиками» открыть договор поставщика, у которого есть заказы (например, `Д-2026/01`).
  2. Записать значения `ПроцентШтрафа` и `МаксимальнаяКомпенсация`.
  **Ожидается:** значения известны — они понадобятся в шагах `ПР.5`–`ПР.6`, чтобы посчитать ожидаемую сумму вручную.

## Справочник «ДоговорыСПоставщиками»

- [ ] **ДГ.1 Корректный договор записывается**
  1. Создать новый элемент.
  2. `Наименование` = «Проверка ДГ», `ДатаНачала` = 01.01.2026, `ДатаОкончания` = 31.12.2026, `ПроцентШтрафа` = 25, `МаксимальнаяКомпенсация` = 50000.
  3. Нажать «Записать».
  **Ожидается:** запись проходит, сообщений нет.
  **После проверки:** пометить на удаление, чтобы не мешал в следующих прогонах наполнения.

- [ ] **ДГ.2 Перевёрнутый период**
  1. В том же элементе поставить `ДатаОкончания` = 01.01.2025 (раньше `ДатаНачала` = 01.01.2026).
  2. Нажать «Записать».
  **Ожидается:** отказ, сообщение «Дата окончания договора раньше даты начала.»
  **Если запись прошла:** правило не сработало — проверять `ПередЗаписью` модуля объекта.

- [ ] **ДГ.3 Процент штрафа вне диапазона**
  1. Вернуть корректные даты, поставить `ПроцентШтрафа` = 120.
  2. Нажать «Записать».
  **Ожидается:** отказ, «Процент штрафа должен быть в диапазоне от 0 до 100.»

- [ ] **ДГ.4 Отрицательный лимит**
  1. Вернуть `ПроцентШтрафа` = 25, поставить `МаксимальнаяКомпенсация` = −1.
  2. Нажать «Записать».
  **Ожидается:** отказ, «Максимальная компенсация не может быть отрицательной.»

- [ ] **ДГ.5 Нулевой процент допустим**
  1. Поставить `ПроцентШтрафа` = 0, `МаксимальнаяКомпенсация` = 0.
  2. Нажать «Записать».
  **Ожидается:** запись проходит. Ноль трактуется как «условие не задано», а не как ошибка.

## Документ «ЗаказПоставщику»

Опорный документ: любой из четырёх заказов демо-набора. Для шагов `ЗП.5`–`ЗП.7` удобнее создать новый, чтобы не портить существующий.

- [ ] **ЗП.1 Итог в шапке**
  1. Открыть заказ.
  **Ожидается:** в шапке есть поле «Сумма документа», значение равно сумме строк табличной части «Услуги». Поле нередактируемое (см. `П.4`).

- [ ] **ЗП.2 Пустой поставщик**
  1. Очистить `Поставщик`.
  2. Нажать «Записать».
  **Ожидается:** отказ, «Не заполнен поставщик заказа. Выберите поставщика из справочника.»

- [ ] **ЗП.3 Пустая табличная часть**
  1. Вернуть поставщика.
  2. Выделить все строки «Услуги» и удалить их (кнопка «Удалить» или `Del`).
  3. Нажать «Записать».
  **Ожидается:** отказ, «Табличная часть "Услуги" пуста. Добавьте хотя бы одну услугу.»

- [ ] **ЗП.4 Подстановка цены из номенклатуры**
  1. Добавить строку.
  2. Выбрать услугу, у которой «Базовая цена» заполнена и не равна нулю (та же, что в `НМ.1`).
  3. Выйти из ячейки (`Tab` или клик в другое поле).
  **Ожидается:** `Цена` подставилась равной «Базовой цене» услуги.
  **Проверка второго условия:** в строке, где цена уже введена вручную, сменить услугу — цена должна остаться прежней.

- [ ] **ЗП.5 Пересчёт строки**
  1. В строке ввести `Количество` = 2.
  2. Ввести `Цена` = 1500 (поверх подставленной).
  3. Выйти из ячейки цены.
  **Ожидается:** `Сумма` строки = 3000,00, «Сумма документа» = 3000,00. Документ не записан и не проведён.
  **Если сумма не изменилась:** обработчик `OnChange` не привязан к колонке.

- [ ] **ЗП.6 Пересчёт итога при добавлении строки**
  1. Добавить вторую строку, услугу, `Количество` = 1, `Цена` = 2000.
  2. Выйти из ячейки.
  **Ожидается:** «Сумма документа» = 5000,00.

- [ ] **ЗП.7 Пересчёт итога при удалении строки**
  1. Выделить вторую строку, нажать «Удалить» (или `Del`).
  2. Нажать «Записать».
  **Ожидается:** «Сумма документа» стала 3000,00 ещё до записи; запись проходит без сообщений о расхождении суммы.
  **Если отказ «Сумма документа (5000,00) не равна сумме строк (3000,00)»:** итог не пересчитался при удалении — дефект.

- [ ] **ЗП.8 Команда «Пересчитать суммы»**
  1. Нажать «Пересчитать суммы».
  **Ожидается:** сообщение «Пересчитано строк: N, сумма документа: X», где N — число строк, X — их сумма.

- [ ] **ЗП.9 Дата ожидания позже начала услуги**
  1. В первой строке поставить `ДатаНачала` = 05.03.2026.
  2. В шапке поставить `ДатаОжиданияПодтверждения` = 10.03.2026.
  3. Нажать «Записать».
  **Ожидается:** отказ, «Дата ожидания подтверждения (10.03.2026) позже начала первой услуги (05.03.2026).»
  **Граница:** если обе даты равны 05.03.2026 — запись должна проходить.

- [ ] **ЗП.10 Чужой договор**
  1. Выбрать `Поставщик` = поставщик А, `Договор` = договор поставщика Б.
  2. Нажать «Записать».
  **Ожидается:** отказ, «Договор … принадлежит другому поставщику. Выберите договор поставщика ….»

- [ ] **ЗП.11 Чужой объект в строке**
  1. Вернуть правильный договор.
  2. В строке выбрать объект, владельцем которого является другой поставщик.
  3. Нажать «Записать».
  **Ожидается:** отказ, «Строка N: объект … принадлежит другому поставщику.»

- [ ] **ЗП.12 Нулевое количество**
  1. Поставить `Количество` = 0 в любой строке.
  2. Нажать «Записать».
  **Ожидается:** отказ, «Строка N: количество должно быть больше нуля.»

- [ ] **ЗП.13 Пустая услуга в строке**
  1. Вернуть количество 1, очистить `Услуга` в строке.
  2. Нажать «Записать».
  **Ожидается:** отказ, «Строка N: не выбрана услуга.»

## Документ «ПодтверждениеУслуги»

Подготовка: открыть заказ с заполненными строками, провести его (или хотя бы записать).

- [ ] **ПУ.1 Создание по основанию**
  1. В заказе нажать «Создать подтверждение».
  2. Дождаться открытия нового документа.
  **Ожидается:** открылся новый `ПодтверждениеУслуги`, заполнены `ЗаказПоставщику`, `Поставщик`, табличная часть `Подтверждённые услуги` повторяет строки заказа (услуга, объект, даты, количество, цена, сумма).
  **Дополнительно:** «Сумма документа» уже равна сумме строк — это ключевая проверка исправленного дефекта.

- [ ] **ПУ.2 Закрытие без записи**
  1. Закрыть созданный документ, отказавшись от записи.
  2. Открыть журнал подтверждений.
  **Ожидается:** нового документа в журнале нет.

- [ ] **ПУ.3 Сверка без расхождений**
  1. Создать подтверждение заново.
  2. Нажать «Выполнить сверку».
  **Ожидается:** сообщение «Все услуги совпадают с заказом. Результат сверки: Совпадает.» Поле `РезультатСверки` = `Совпадает`.

- [ ] **ПУ.4 Расхождение по питанию**
  1. В первой строке изменить `ТипПитанияФакт` на значение, отличное от заказа.
  2. Нажать «Выполнить сверку».
  **Ожидается:** сообщение «Строка 1: тип питания "…" вместо "…".», затем «Результат сверки: ЕстьРасхождения. Расхождений: 1.»
  **Визуально:** `РезультатСверки` = `ЕстьРасхождения`.

- [ ] **ПУ.5 Чужой поставщик**
  1. Сменить `Поставщик` на любого другого.
  2. Нажать «Записать».
  **Ожидается:** отказ, «Поставщик подтверждения (…) не совпадает с поставщиком заказа (…).»

- [ ] **ПУ.6 Услуга, которой нет в заказе**
  1. Вернуть правильного поставщика.
  2. Добавить строку, выбрать услугу, которой нет в заказе, и любой объект.
  3. Нажать «Записать».
  **Ожидается:** отказ, «Строка N: услуга … по объекту … отсутствует в заказе поставщику.»

- [ ] **ПУ.7 Пересчёт итога после удаления строки**
  1. Удалить добавленную строку.
  2. Нажать «Записать».
  **Ожидается:** «Сумма документа» равна сумме оставшихся строк, запись проходит.

## Документ «ПретензияПоставщику»

Подготовка: нужен инцидент с поставщиком и действующим договором этого поставщика. Проще всего открыть инцидент и нажать «Создать претензию».

- [ ] **ПР.1 Превышение порога без согласования**
  1. Создать претензию по инциденту.
  2. Поставить `СуммаТребования` = 60000.
  3. Оставить `СогласованоРуководителем` = Ложь.
  4. Нажать «Записать».
  **Ожидается:** отказ, «Сумма требования (60000,00) превышает порог согласования (50000,00). Требуется согласование руководителем.»

- [ ] **ПР.2 Превышение порога с согласованием**
  1. Поставить `СогласованоРуководителем` = Истина.
  2. Нажать «Записать».
  **Ожидается:** запись проходит.

- [ ] **ПР.3 Нулевая сумма**
  1. Поставить `СуммаТребования` = 0.
  2. Нажать «Записать».
  **Ожидается:** отказ, «Сумма требования должна быть больше нуля.»

- [ ] **ПР.4 Чужой договор**
  1. Выбрать договор другого поставщика.
  2. Нажать «Записать».
  **Ожидается:** отказ, «Договор … принадлежит другому поставщику.»

- [ ] **ПР.5 Расчёт компенсации**
  1. Вернуть договор своего поставщика, `ПроцентШтрафа` = 25, `МаксимальнаяКомпенсация` = 50000 (см. `ДГ.1`).
  2. Нажать «Рассчитать компенсацию».
  **Ожидается:** сообщение «Рассчитана компенсация: X (исходная расчётная: Y)». Если Y превысил 50 000 — добавляется «, ограничена максимальной компенсацией договора», и X = 50000. Если сумма больше порога — добавляется «. Требуется согласование руководителем.»
  **Проверка арифметики:** базовая стоимость берётся как максимальная сумма строк заказа по паре «заявка на тур + поставщик + объект»; расчёт = базовая × 25% × 1 день.

- [ ] **ПР.6 Неудачный расчёт не обнуляет сумму**
  1. Вписать в `СуммаТребования` вручную 90000.
  2. Выбрать договор, у которого `ПроцентШтрафа` = 0.
  3. Нажать «Рассчитать компенсацию».
  **Ожидается:** сообщение «Расчёт невозможен: Процент штрафа не задан.», а `СуммаТребования` осталась 90000.
  **Если стала 0:** дефект исправления — расчёт затирает введённое значение.

## Документ «АктОКомпенсации»

Подготовка: претензия с `СуммаТребования` = 70000.

- [ ] **АК.1 Взыскание больше требования**
  1. Создать акт по претензии.
  2. Поставить `СуммаВзысканияСПоставщика` = 90000.
  3. Нажать «Записать».
  **Ожидается:** отказ, «Сумма взыскания с поставщика (90000,00) превышает сумму требования по претензии (70000,00).»

- [ ] **АК.2 Структура не сходится с итогом**
  1. Поставить `СуммаКомпенсацииТуристу` = 35000.
  2. В табличной части `Структура компенсации` оставить строки на 30000.
  3. Нажать «Пересчитать структуру».
  **Ожидается:** сообщение «Строки дают 30000,00, итог акта 35000,00, разница 5000,00.»
  4. Нажать «Записать».
  **Ожидается:** отказ, «Сумма строк структуры (30000,00) не равна сумме компенсации туристу (35000,00). Пересчитайте структуру.»

- [ ] **АК.3 Суммы сходятся**
  1. Привести строки к 35000 (или наоборот, поставить итог 30000).
  2. Нажать «Пересчитать структуру» — сообщение «Структура сходится с итогом: …».
  3. Нажать «Записать».
  **Ожидается:** запись проходит.

- [ ] **АК.4 Пустая структура**
  1. Удалить все строки табличной части.
  2. Нажать «Записать».
