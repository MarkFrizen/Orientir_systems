# dataset-verification Specification

## Purpose

Проверка наполненной инфобазы: инвентаризация фактических количеств, поиск несогласованных ссылок и нарушений ограничений, итоговый вердикт о пригодности демонстрационного набора.

## Requirements

### Requirement: Отчёт о фактических количествах

Проверка ДОЛЖНА выводить в лог-файл количество элементов по каждому справочнику и документу демонстрационного набора, а также итоговый вердикт.

#### Scenario: Запуск проверки на наполненной базе

- **WHEN** проверка запущена на наполненной базе
- **THEN** лог содержит строку с количеством для каждого справочника и документа
- **AND** последняя строка содержит вердикт «PASS» или «FAIL»

### Requirement: Обнаружение несогласованных ссылок

Проверка ДОЛЖНА находить пустые обязательные ссылки и ссылки на объекты, помеченные на удаление, во всех справочниках и документах набора.

#### Scenario: Ссылка на помеченный на удаление объект

- **WHEN** документ ссылается на поставщика, помеченного на удаление
- **THEN** проверка сообщает вид документа, реквизит и проблему
- **AND** итоговый вердикт — «FAIL»

#### Scenario: Пустая обязательная ссылка

- **WHEN** у «МаршрутныйЛист» не заполнен гид
- **THEN** проверка фиксирует нарушение по этому документу

### Requirement: Контроль ограничений Дополнения к ТЗ

Проверка ДОЛЖНА контролировать правила п. 5.3: дата начала не позже даты окончания, дата инцидента не позже текущей даты, суммы не отрицательны, сумма взыскания не превышает сумму требования.

#### Scenario: Перевёрнутый период

- **WHEN** у документа дата окончания раньше даты начала
- **THEN** проверка фиксирует нарушение временной целостности

#### Scenario: Отрицательная сумма

- **WHEN** в документе или табличной части встретилась отрицательная сумма
- **THEN** проверка фиксирует нарушение финансовой целостности

### Requirement: Соответствие целевым объёмам

Проверка ДОЛЖНА сравнивать фактические количества с целевыми и сообщать расхождение в формате «факт из цели».

#### Scenario: Недобор по справочнику

- **WHEN** «Поставщики» содержит двенадцать элементов при цели восемнадцать
- **THEN** проверка сообщает «12 из 18»
- **AND** итоговый вердикт — «FAIL»

### Requirement: Проверка не изменяет данные

Проверка ДОЛЖНА работать в режиме чтения: не записывать объекты, не менять реквизиты и не формировать движения.

#### Scenario: Повторный запуск проверки

- **WHEN** проверка запущена дважды подряд
- **THEN** результаты обоих запусков совпадают
- **AND** в базе не появляется новых объектов

### Requirement: Контроль объёма базы

Проверка ДОЛЖНА выводить размер файла информационной базы и признак того, укладывается ли он в лимит учебной версии платформы.

#### Scenario: Отчёт о размере

- **WHEN** проверка запущена
- **THEN** в логе указан размер файла базы в мегабайтах и вывод «в пределах лимита» либо «превышен»
