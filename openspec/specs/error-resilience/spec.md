# error-resilience Specification

## Purpose

Гарантирует, что нештатные операции (действия без прав, некорректные данные, конфликтующие повторные операции) завершаются для пользователя понятным отказом без аварий платформы и без повреждения данных — поверх существующих правил отклонения записи и матрицы прав.

## Requirements

### Requirement: Отклонённая операция не порождает аварию платформы

Любая операция, отклоняемая системой (правилами записи, проведением, обменом), SHALL завершаться сообщением пользователю; платформенное исключение с дампом ошибки, зависание или незавершённый транзакционный блок НЕ ДОПУСКАЮТСЯ ни в интерактивном режиме, ни при программном вызове из обработок.

#### Scenario: Интерактивная запись с нарушением правила записи

- **WHEN** пользователь записывает документ с отрицательным количеством в табличной части
- **THEN** запись отклонена, в журнале сообщений перечислены нарушения, приложение работает дальше без дампа ошибки

#### Scenario: Программная запись из внешней обработки

- **WHEN** обработка проводит пакет объектов, и один из них отклонён правилами объекта
- **THEN** обработка продолжает пакет, в отчёте этот объект помечен с причиной, исключение наружу не выпущено

### Requirement: Отказ доступа формулируется как понятный запрет

Операция, на которую у текущей роли нет прав, SHALL приводить либо к недоступности команды (командный интерфейс/права платформы скрывают её), либо к сообщению с указанием действия и объекта; платформенный текст «Действо не разрешено» без объяснения SHALL дополняться контекстом операции.

#### Scenario: Гид пытается создать заказ поставщику

- **WHEN** пользователь с ролью `Профиль_Гид` (без прав добавления на `ЗаказПоставщику`) открывает раздел, где команда доступна оператору
- **THEN** команда создания недоступна либо вызов завершается сообщением, что для этого действия нужна роль оператора сопровождения

#### Scenario: Вызов обработки без права на ключевой объект

- **WHEN** пользователь без права «Добавление» на `Document.ЗаказПоставщику` запускает обработку «Формирование запросов поставщикам»
- **THEN** обработка останавливается на проверке прав с сообщением «Недостаточно прав для …», отчёта о формировании нет

#### Scenario: Открытие внешней обработки тестовой учётной записью без инфраструктурной роли

- **WHEN** пользователь без роли `ТестоваяИнфраструктура` пытается интерактивно открыть внешнюю обработку
- **THEN** платформа отказывает в открытии, конфигурация не зависает, отказ воспроизводится одинаково в тонком клиенте и веб-клиене

### Requirement: Отклонение не оставляет частично изменённых данных

Отказ в любой многошаговой операции (проведение, корректировка, загрузка CSV) SHALL откатывать все изменения этой операции: документ остаётся в прежнем состоянии, регистры — без движений текущей попытки, уже загруженные успешные строки пакета — сохранёнными.

#### Scenario: Ошибка посреди проведения

- **WHEN** проведение `АктОКомпенсации` прерывается из-за расхождения сумм табличной части и итога
- **THEN** движения ни в один регистр не записаны, статус связанного инцидента не изменён, документ не помечен проведённым

#### Scenario: Пакетная загрузка с битой строкой

- **WHEN** CSV-загрузка содержит корректные строки и одну строку с неразрешимой ссылкой
- **THEN** корректные строки записаны, битая отклонена с указанием номера строки и причины, повтор загрузки не удваивает уже загруженные объекты

### Requirement: Повторные и конфликтующие операции идемпотентны

Повторение операции над тем же объектом (повторное проведение, повторная загрузка того же файла, повторное нажатие команды) SHALL завершаться без дублей записей регистров и объектов; обнаруживаемый конфликт ключей (код/наименование справочника, измерение регистра, строка файла против существующего объекта) отклоняется с указанием конфликтующего значения.

#### Scenario: Повторное проведение проведённого документа

- **WHEN** документ, имеющий движения, проведён повторно без изменений
- **THEN** набор движений идентичен предыдущему, удвоенных записей в регистрах нет

#### Scenario: Повторная загрузка того же CSV

- **WHEN** файл, уже загруженный полностью, загружается второй раз
- **THEN** все строки отклонены как дубли с указанием значения ключа, количество объектов в базе не изменилось
