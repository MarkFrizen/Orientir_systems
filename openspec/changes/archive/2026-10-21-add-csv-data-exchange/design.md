# Design

## Context

Мотивация — в `proposal.md`. Здесь только то, что определяет подход.

- Конфигурация `КурсоваяРабота`, платформа 8.3.27.1786, файловая ИБ `db/КурсоваяРабота`, исходники `src/КурсоваяРабота`. См. `.v8-project.json`.
- В составе конфигурации **нет ни одной обработки**: тег `Processing` в `Configuration.xml` отсутствует. Все утилиты до сих пор жили вне конфигурации: `epf/ПроверкаДанных`, `epf/ЗаполнениеНСИ`.
- В конфигурации **нет ни одного приёма файлового ввода-вывода**: греп по `src/**/*.bsl` не находит `ЧтениеТекста`, `ЗаписьТекста`, `ПрочитатьXML`, `ЗаписатьXML`, `СтрРазделить`.
- Правила записи вынесены в экспортную функцию `ПравилаЗаписи(Объект)` модуля объекта и вызываются как метод объекта: `Заказ.ПравилаЗаписи(Заказ)` — так это уже делает `epf/ПроверкаДанных/Forms/Форма/Ext/Form/Module.bsl:395`. `ПередЗаписью` вызывает ту же функцию и публикует нарушения через `СообщениеПользователю`.
- `ПередЗаписью` обоих объектов пропускает проверки при `ОбменДанными.Загрузка = Истина`. Этот флаг — ловушка: включив его, легко протащить в базу мусор в обход правил.
- `НоменклатураУслуг`: `CheckUnique = false`, иерархия `HierarchyFoldersAndItems`, `LevelCount = 2`, `CodeLength = 9`, `DescriptionLength = 25`, реквизиты `ВидУслуги` (перечисление `ВидыУслуг`), `Единица`, `БазоваяЦена` (15.2), `Валюта`.
- `ЗаказПоставщику`: `Posting = Allow`, реквизиты шапки `ЗаявкаНаТур`, `Поставщик`, `Договор`, `ДатаОжиданияПодтверждения`, `Статус` (перечисление `СтатусыЗаказа`), `Комментарий`, `Ответственный`, `СуммаДокумента`; ТЧ `Услуги` из десяти реквизитов; `NumberLength = 11`, `NumberPeriodicity = Year`, `CheckUnique = true`.
- Обработка в конфигурации **не запускается из командной строки через `/Execute`** — этот ключ принимает только внешние обработки. Значит, для автотестов нужен драйвер-EPF.
- Грабли проекта (`docs/Оставшиеся-задачи.md`): строки длиннее 1024 символов в файловой ИБ не принимаются; JSON/PS1 сохранять в UTF-8 с BOM; команды к базе требуют `-UserName "Администратор"`; `ТекущаяДатаСеанса()` недоступна на тонком клиенте; двойной BOM ломает XML.
- Роль `Администратор` объявлена без явных `<object>`-прав, через `setForNewObjects = true`, поэтому новые объекты получают права автоматически.

## Goals / Non-Goals

**Goals:**

- Один предсказуемый формат файла в обе стороны, пригодный для правки в Excel.
- Загрузка проходит те же правила, что и ручной ввод, и не умеет их обходить.
- Ошибка в одной записи не отменяет загрузку остальных и не оставляет документ наполовину записанным.
- Отчёт пригоден и для человека на форме, и для автотеста — машиночитаемый вердикт.
- Автотесты не портят демо-набор.

**Non-Goals:**

- Универсальный обмен по произвольным объектам метаданных.
- Форматы, кроме CSV: XML, JSON, XLSX, MXL.
- Режим «обновить существующий элемент» и автосоздание отсутствующих ссылок.
- Обмен по сети, HTTP-сервисы, очереди.
- Выгрузка вложений и файловых реквизитов.

## Decisions

### 1. Обработка в конфигурации, механика CSV — в общем модуле

Новый объект `Processing.ОбменСФайлами` + новый общий модуль `ОбменCSV`.

`ОбменCSV` не знает про номенклатуру и заказы: только разбор и сборка строк, чтение и запись файла, приведение значений к типам. Свойства модуля — как у трёх существующих: `Сервер = Истина`, `ВызовСервера = Ложь`, `Клиент = Ложь`, `ВнешнееСоединение = Истина`, `Привилегированный = Ложь`.

Альтернатива — вся логика в модуле обработки — отклонена: парсер CSV понадобится и драйверу автотестов, и любому следующему формату обмена. Альтернатива — два общих модуля (механика + домен) — отклонена: доменная логика принадлежит обработке, ради которой она и написана.

### 2. Формат файла: UTF-8 с BOM, `;`, десятичная запятая, ISO-даты

- кодировка UTF-8, маркер BOM — чтобы Excel не превращал кириллицу в кракозябры;
- разделитель полей `;` — потому что запятая занята десятичным разделителем в русской локали;
- даты `ГГГГ-ММ-ДД` — однозначны и не зависят от региональных настроек; `ДД.ММ.ГГГГ` в русской локали тоже читается, но при обмене с чужим Excel ломается;
- логические `Истина` / `Ложь`;
- пустое значение — пустая строка.

Альтернатива — разделитель `,` и точка в десятичных — отклонена: русский Excel по умолчанию пишет `1,5`, и файл перестаёт открываться «в две колонки».

### 3. Заказы выгружаются плоским файлом, документ собирается по номеру

Одна строка файла — одна строка ТЧ `Услуги`; реквизиты шапки повторяются. `СуммаДокумента` в файл не пишется: при загрузке она пересчитывается как сумма строк, иначе `ПравилаЗаписи` отвергнет документ из-за расхождения итога.

Альтернатива — два файла «шапки» и «строки» — отклонена: пользователь обязан помнить про парность файлов, а при правке одного из них данные расходятся молча. Альтернатива — шапка только в первой строке группы — отклонена: в Excel такая таблица не сортируется и не фильтруется.

### 4. Уникальность — по коду, но платформа её не гарантирует

`CheckUnique = false`, поэтому проверку уникальности делает сама загрузка: код, повторённый в файле или уже существующий в базе, отклоняется. Если в базе уже есть несколько элементов с одним кодом, загрузка сообщает о неоднозначности и не угадывает.

Альтернатива — уникальность по наименованию — отклонена: `DescriptionLength = 25`, наименования повторяются между группами. Альтернатива — включить `CheckUnique` в метаданных — отклонена: это изменило бы поведение интерактивного ввода за пределами задачи и потребовало бы чистить существующие данные.

### 5. Ссылки разрешаются по представлению, и только там, где это однозначно

- `Договор` ищется **среди договоров выбранного поставщика**, `Объект` — среди объектов этого поставщика. Это не оптимизация, а сужение области поиска: одинаковые номера договоров у разных поставщиков — норма.
- `ВидУслуги`, `Статус` — по представлению перечисления.
- `Единица`, `Валюта`, `Поставщик`, `ЗаявкаНаТур`, `Услуга`, `Ответственный` — по наименованию справочника.
- Найдено ноль или больше одного — ошибка строки с перечнем кандидатов.

Альтернатива — ссылки по `UUID` — отклонена: файл перестаёт быть редактируемым человеком. Альтернатива — путь `Родитель/Наименование` для иерархических справочников — отложена: усложняет формат ради редкого случая, а неоднозначность и так видна в отчёте.

### 6. Порядок проверок — от дешёвых к дорогим, запись последней

Для каждой единицы обмена:

1. формат строки — число полей совпадает с заголовком;
2. типы — число, дата, булево, перечисление;
3. ссылки — всё разрешилось в существующие объекты;
4. уникальность — кода нет в файле и в базе;
5. сборка объекта в памяти;
6. `ПравилаЗаписи(Объект)` — доменные правила;
7. запись в собственной транзакции.

Проверка `ПравилаЗаписи` до записи — единственный способ получить текст нарушения: `ПередЗаписью` только публикует сообщения и ставит `Отказ`, не возвращая причины.

### 7. `ОбменДанными.Загрузка` не включается

Загрузка идёт с `ОбменДанными.Загрузка = Ложь`, то есть через обычные проверки. Соблазн выставить флаг и «протолкнуть» данные отвергнут: это ровно тот обход правил, от которого предостерегает `data-validation`.

### 8. Транзакция на единицу обмена, документ — атомарно

`НачатьТранзакцию()` / `ЗафиксироватьТранзакцию()` вокруг одной единицы. Для документа единица — весь документ со всеми строками файла с тем же номером.

После `Записать()` проверяется, что `Ссылка` заполнилась. `Записать()` не бросает исключение при `Отказ`, поэтому без этой проверки неудачная запись выглядела бы успешной.

### 9. Три вердикта вместо двух

`PASS` — записано всё; `ЧАСТИЧНО` — записана часть; `FAIL` — не записано ничего. Два вердикта не различают «ничего не загрузили» и «загрузили половину», а это разные реакции пользователя.

### 10. Отчёт — таблица на форме плюс текстовый файл

Таблица: `Строка`, `Уровень`, `Объект`, `Сообщение`. Текстовый файл `<имя файла данных>.report.txt` рядом с файлом данных — с шапкой, счётчиками, списком ошибок и итоговым вердиктом.

Файл нужен не «для красоты»: автотест сверяет вердикт и текст ошибок, не разбирая форму.

### 11. Драйвер автотестов — отдельная внешняя обработка

`epf/ТестОбмена` с одной формой: `ПриОткрытии` разбирает `ПараметрЗапуска` вида `сценарий|путьКФайлу|путьКОтчёту`, вызывает `Обработки.ОбменСФайлами.Создать()` и его экспортные методы, пишет лог и завершает работу.

Альтернатива — обработчик в модуле приложения по ключу `/C` — отклонена: пришлось бы держать тестовый код в рабочей конфигурации. Альтернатива — автотест через Vanessa BDD — отклонена: раннер 6.9.5 не работает на 8.3.27.

### 12. Тестовые данные изолированы префиксом и очисткой

Все объекты, создаваемые тестами, получают наименование с префиксом `ТЕСТ-` и код `999…`. Перед прогоном и после каждого сценария драйвер удаляет всё с этими признаками.

Это позволяет держать `demo-dataset` неизменным: количества демо-набора возвращаются к исходным, `epf/run-check.ps1` продолжает давать `PASS`.

Альтернатива — отдельная временная ИБ — отклонена: плюс 1–2 минуты на каждый прогон и ещё одна точка отказа.

### 13. Обработка входит в «Администратор ИС», а не в «Справочники НСИ»

`СправочникиНСИ` собрана из справочников, а обмен затрагивает и документы. Административный раздел — более честное место. Права правятся не вручную: `setForNewObjects = true` в роли `Администратор` покрывает новые объекты.

## Risks / Trade-offs

- **Неоднозначные наименования ссылок** → загрузка отклоняет строку и печатает кандидатов; пользователь уточняет значение в файле. Массового автоисправления нет намеренно.
- **Плоский файл заказов раздувается** при большом числе строк ТЧ → для 20 документов демо-набора это сотни строк, не проблема; при росте объёма формат придётся пересматривать.
- **Правка кода в Excel съедает ведущие нули** → код `000000042` превращается в `42`. Митигация: загрузка не падает, а сообщает, что код не найден, и предлагает проверить формат ячейки; в отчёте печатается исходное значение.
- **Частичная загрузка оставляет базу в промежуточном состоянии** → это осознанное требование, но пользователь должен видеть вердикт `ЧАСТИЧНО` и список отклонённых строк; повторный запуск того же файла создаст дубли по уже записанным строкам и вернёт `FAIL` — это ожидаемо и описано в отчёте.
- **Кириллица в путях к файлам** → 1С работает с такими путями штатно, но PowerShell-скрипт должен передавать путь в UTF-8 и без лишних кавычек.
- **Файловая ИБ и одновременный доступ** → лицензия на одно место, тесты и ручная работа не должны идти параллельно.
- **Новый общий модуль и обработка требуют переиндексации LSP** → после `db-load-xml` проверить `root_path` и `status: ready`, иначе `1c-lsp-diagnostics` вернёт «Проект еще не готов».

## Migration Plan

1. Бэкап: `db-dump-dt` файловой ИБ `db/КурсоваяРабота`.
2. Метаданные: `CommonModules/ОбменCSV.xml`, `DataProcessors/ОбменСФайлами.xml`, форма обработки, `Processing.ОбменСФайлами` в `Configuration.xml`, объект в `<Content>` подсистемы `АдминистраторИС`.
3. Код общего модуля `ОбменCSV` и проверка парсера на строках с кавычками, разделителями и переводами строк.
4. Модуль объекта обработки: выгрузка и загрузка номенклатуры, затем заказов, затем отчёт.
5. Форма обработки: путь к файлу, период, четыре команды, таблица результатов, вердикт.
6. Драйвер `epf/ТестОбмена` и сборка `build/ТестОбмена.epf`.
7. `db-load-xml` + обновление конфигурации БД с `-UserName "Администратор"`.
8. `1c-lsp-diagnostics`, `form-validate`, `/CheckModules -ThinClient`.
9. `epf/run-check.ps1` — обязан остаться `PASS`, демо-набор не тронут.
10. `tests/exchange/run-exchange-tests.ps1` — все сценарии зелёные.
11. `tests/vanessa/run-xdd-smoke.ps1` — 82/82 плюс сценарий формы обмена.
12. Обновить `docs/Оставшиеся-задачи.md`.

**Откат**: `db-load-dt` из бэкапа шага 1 и `git revert` коммита изменения. Порядок важен: сначала восстанавливается база, потом откатывается код, иначе конфигурация и ИБ разойдутся по составу объектов.

## Open Questions

- Нужна ли выгрузка «только выбранных пользователем» элементов по отбору списка, помимо полной выгрузки справочника? Формат файла от этого не меняется — добавляется только построение отбора, поэтому решение можно отложить.
- Нужен ли фильтр по поставщику при выгрузке заказов, кроме периода? Сейчас период закрывает сценарий; добавление фильтра не ломает контракт файла.
