# Design

## Context

См. `proposal.md` — Why. Факты по текущему состоянию:

- `Subsystems/Сервис.xml` содержит 22 объекта: константа `ПорогСогласованияРуководителем`, `ChartOfCharacteristicTypes.ДополнительныеРеквизитыТуриста`, `ChartOfCharacteristicTypes.ДополнительныеРеквизитыУслуг`, `Task.ЗадачаИсполнителя`, `InformationRegister.АдресацияЗадач` и все 17 перечислений.
- `Subsystems/Сервис/Ext/CommandInterface.xml` скрывает команды регистра, обоих планов видов характеристик и константы.
- `Subsystems/АдминистраторИС.xml` имеет пустой `<Content/>` и две дочерние подсистемы: `СправочникиНСИ` (12 объектов) и `НастройкиИнтеграций` (регистр `НастройкиИнтеграций`, рабочая).
- `Roles/Администратор/Ext/Rights.xml` содержит только флаги `setForNewObjects` и `setForAttributesByDefault`, ни одного объекта.
- Пользователь в базе один — администратор информационной базы, поэтому права роли сейчас ни на что не влияют.
- Совместимость `Version8_3_27`, управляемое приложение, файловая ИБ.

## Goals / Non-Goals

**Goals:**

- Порог согласования открывается и редактируется из раздела «Администратор ИС».
- Раздел «Сервис» исчезает, его объекты не теряются.
- Технические объекты (планы характеристик, задача, регистр адресации) не занимают панель навигации.
- «Настройки интеграций» остаются нетронутыми.

**Non-Goals:**

- Семь профилей групп доступа и реальное разделение «администратор ИС / администратор 1С» — отдельная задача этапа 3.
- RLS-ограничения и права на остальные объекты.
- Изменение семантики порога и правила проверки претензии.
- Перенос перечислений в другие подсистемы.

## Decisions

### 1. Подсистема «Сервис» удаляется, а не переименовывается

Её назначение дублирует «Администратор ИС»: технические объекты и настройки. Переименование оставило бы два раздела с одинаковым смыслом. Альтернатива — оставить «Сервис» как свалку — отклонена: пустой раздел в интерфейсе хуже, чем его отсутствие.

### 2. Объекты переезжают в корень «Администратор ИС», без новой дочерней подсистемы

Пять объектов, из которых видим будет один. Создавать дочернюю подсистему ради одного элемента — лишний уровень вложенности в навигации. Альтернатива — дочерняя «Параметры» — отклонена по этой причине.

### 3. Перечисления не переносятся никуда

У перечислений нет навигационных команд, в интерфейсе они не видны. Держать их в составе подсистемы имеет смысл только как документацию состава, а «Администратор ИС» от этого станет свалкой. Системный администратор при необходимости правит значения в Конфигураторе. Альтернатива — сложить все 17 в «Администратор ИС» — отклонена.

### 4. Видимой остаётся только константа

Команды планов видов характеристик, задачи исполнителя и регистра `АдресацияЗадач` явно скрываются в командном интерфейсе «Администратор ИС». Они технические и открываются из связанных документов. Это согласуется с уже действующим требованием спеки «Технические команды скрыты в панелях навигации».

### 5. Роль получает права чтения и изменения на константу

Без права `Изменение` форма константы откроется только на просмотр, и цель изменения не достигается. Права добавляются только на константу: выдавать роли права на остальные объекты в этом изменении нельзя — это задача профилей. Альтернатива — не трогать права, полагаясь на статус администратора ИБ — отклонена: тогда «админ ИС» и «админ 1С» остаются одним и тем же лицом даже формально.

### 6. «Настройки интеграций» не трогаем

Подсистема содержит регистр `НастройкиИнтеграций` и работает. Любые правки её состава — риск сломать существующую навигацию без выгоды.

## Risks / Trade-offs

- **Удаление подсистемы меняет привычный интерфейс.** → Раздел пуст, потерь для пользователя нет; в документации обновляется перечень подсистем.
- **Права добавлены частично, роль остаётся почти пустой.** → Пока нет профилей, фактический доступ определяется статусом администратора ИБ. Ограничение зафиксировано в proposal и в `docs/Оставшиеся-задачи.md`.
- **Перечисления остаются без подсистемы.** → Навигация не страдает, состав конфигурации сохраняется; проверяется `cf-validate` и `/CheckModules`.
- **Ошибка в `Configuration.xml` при удалении подсистемы.** → Бэкап ИБ до загрузки, `cf-validate` до и после, откат через `git revert` и `db-load-dt`.
- **Скрытие команд технических объектов может скрыть что-то нужное.** → Перед загрузкой проверяется список: скрываются ровно четыре команды, названные в решении 4.

## Migration Plan

1. Бэкап ИБ (`db-dump-dt`).
2. Удалить `Subsystems/Сервис.xml`, каталог `Subsystems/Сервис/` и `<Subsystem>Сервис</Subsystem>` из `Configuration.xml`.
3. Добавить пять объектов в `<Content>` подсистемы `АдминистраторИС`.
4. В `Subsystems/АдминистраторИС/Ext/CommandInterface.xml` вывести команду константы и скрыть команды четырёх технических объектов.
5. Добавить права `Read` и `Update` на константу в `Roles/Администратор/Ext/Rights.xml`.
6. Проверки: `cf-validate`, `meta-validate` подсистем, `/CheckModules`, `1c-lsp-diagnostics`.
7. Загрузка с обновлением БД, `run-check.ps1`, xdd-смоук.
8. Откат: `db-load-dt` из бэкапа шага 1 плюс `git revert`.

## Open Questions
