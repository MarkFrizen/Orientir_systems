# Spec Delta

## Purpose

Команды на формах и навигация разделов дают пользователю быстрый доступ к типовым операциям рабочего места — открыть связанный объект, создать документ на основании, отобрать просроченные — без ручных переходов через главное меню.

## ADDED Requirements

### Requirement: Навигационные команды карточки открывают связанные объекты

Карточки документов и справочников, содержащие ссылочные реквизиты, SHALL предоставлять команды открытия связанных объектов. Команда SHALL открывать форму существующего объекта и SHALL быть недоступна, если ссылка не заполнена.

#### Scenario: Открытие заявки из заказа поставщику

- **WHEN** пользователь в карточке `ЗаказПоставщику` нажимает команду «Открыть заявку»
- **THEN** открывается форма элемента справочника `ЗаявкиНаТур` с заполненной ссылкой из реквизита `ЗаявкаНаТур`

#### Scenario: Пустая ссылка

- **WHEN** реквизит `ЗаявкаНаТур` не заполнен
- **THEN** команда «Открыть заявку» недоступна

### Requirement: Создание документа на основании

Карточки документов, для которых определён сценарий «документ на основании», SHALL предоставлять команду создания нового документа с переносом реквизитов и табличных частей. Перечень связей: `ЗаказПоставщику` → `ПодтверждениеУслуги`, `Инцидент` → `ПретензияПоставщику`, `ПретензияПоставщику` → `АктОКомпенсации`.

#### Scenario: Создание претензии по инциденту

- **WHEN** пользователь в карточке `Инцидент` нажимает «Создать претензию»
- **THEN** открывается новая карточка `ПретензияПоставщику` с заполненными `Инцидент`, `Поставщик`, `Договор` и суммой по данным инцидента

#### Scenario: Отмена создания на основании

- **WHEN** пользователь закрывает созданную карточку без записи
- **THEN** новый документ не создаётся, исходный документ не изменяется

### Requirement: Сервисные команды журнала управляют отбором

Журналы с контрольными датами SHALL предоставлять команды «Показать просроченные» и «Сбросить отбор». Команда отбора SHALL устанавливать отбор динамического списка по контрольной дате и незавершённым статусам, не изменяя данные.

#### Scenario: Отбор просроченных заказов

- **WHEN** пользователь в журнале `ЗаказПоставщику` нажимает «Показать просроченные»
- **THEN** в списке остаются только строки с `ДатаОжиданияПодтверждения` меньше текущей даты и статусом `Отправлен` или `ЧастичноПодтверждён`

#### Scenario: Сброс отбора

- **WHEN** пользователь нажимает «Сбросить отбор»
- **THEN** список показывает все документы, доступные пользователю по правам, в исходной сортировке

### Requirement: Команды-заготовки этапа 4

Карточки документов SHALL содержать по одной команде-заготовке для будущих расчётов: `ПодтверждениеУслуги` — «Выполнить сверку», `ЗаказПоставщику` — «Пересчитать суммы», `МаршрутныйЛист` — «Пересчитать тайминги», `СобытиеМаршрута` — «Пересчитать локальное время», `ЗаявкаТуристаНаМаршруте` — «Рассчитать срок SLA», `ПретензияПоставщику` — «Рассчитать компенсацию», `Инцидент` — «Классифицировать», `КорректировкаМаршрута` — «Применить корректировку», `АктОКомпенсации` — «Пересчитать структуру».

#### Scenario: Команда-заготовка присутствует

- **WHEN** пользователь открывает карточку `ПодтверждениеУслуги`
- **THEN** в командной панели формы доступна команда «Выполнить сверку»

#### Scenario: Полный перечень заготовок

- **WHEN** проверяются карточки девяти документов
- **THEN** в каждой найдена ровно одна команда-заготовка из перечня выше, без дублей стандартных команд платформы

### Requirement: Заготовка не изменяет данные

Обработчик команды-заготовки SHALL выводить информационное сообщение о том, что логика появится на этапе 4, и SHALL NOT записывать документ, менять его статус или создавать движения.

#### Scenario: Вызов заготовки в незаписанном документе

- **WHEN** пользователь в незаписанной карточке `ЗаказПоставщику` нажимает «Пересчитать суммы»
- **THEN** выводится сообщение о том, что расчёт будет реализован на этапе 4, документ остаётся непроведённым и незаписанным

#### Scenario: Заготовка не создаёт движений

- **WHEN** пользователь вызывает заготовку в записанном проведённом документе
- **THEN** движения регистров не меняются, статус документа не меняется

### Requirement: Команды подчиняются правам доступа

Команды, изменяющие данные или создающие объекты, SHALL быть доступны только пользователям с соответствующими правами. При отсутствии прав команда SHALL быть скрыта или недоступна, а вызов из кода SHALL завершаться отказом без изменения данных.

#### Scenario: Пользователь без прав на инциденты

- **WHEN** пользователь без права добавления документов `Инцидент` открывает карточку `Инцидент` в режиме просмотра
- **THEN** команда «Создать претензию» недоступна, остальные команды просмотра работают

### Requirement: Панель навигации подсистемы содержит типовые операции

Каждая листовая подсистема SHALL содержать в панели навигации команды «Открыть <список>» и «Создать <объект>» для своих объектов, упорядоченные по частоте использования. Команды объектов, не входящих в подсистему, SHALL отсутствовать.

#### Scenario: Навигация оператора сопровождения

- **WHEN** пользователь открывает раздел «Оператор сопровождения» и подраздел «Заказы поставщикам»
- **THEN** в панели навигации первыми стоят команды открытия журнала `ЗаказПоставщику` и создания нового заказа, а команды объектов других подсистем отсутствуют

#### Scenario: Навигация гида

- **WHEN** пользователь открывает подраздел «Новый инцидент»
- **THEN** в панели навигации доступны открытие журнала `Инцидент` и создание нового инцидента

### Requirement: Технические команды скрыты в панелях навигации

Регистры, бизнес-процессы и задачи, входящие в подсистему только для служебных целей, SHALL быть скрыты в панели навигации. Их команды SHALL оставаться доступными через формы связанных документов.

#### Scenario: Скрытые регистры в подразделе «Подтверждения»

- **WHEN** пользователь открывает подраздел «Подтверждения»
- **THEN** в панели навигации видны команды `ПодтверждениеУслуги`, а команды регистров `СтатусыПодтверждений` и `ПараметрыУслуг` скрыты
