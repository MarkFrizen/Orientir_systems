# Design

## Context

См. `proposal.md` — мотивация. Ниже только то, что определяет подход.

- Файловая ИБ `db/КурсоваяРабота` (платформа 8.3.27.1786), исходники `src/КурсоваяРабота`, лицензия на одно рабочее место.
- Наполнение уже реализовано внешней обработкой `epf/ЗаполнениеНСИ`: объектный модуль пуст, вся логика — в модуле формы (`Forms/Форма/Ext/Form/Module.bsl`). Запуск — `epf/run-fill.ps1` через `/Execute ... /C "<путь_лога>"`; `ПриОткрытии` вызывает `ВыполнитьЗаполнение(ПараметрЗапуска)` и закрывает программу.
- Обработка умеет создавать НСИ, сотрудников, типы запросов и инцидентов, поставщиков, договоры, объекты гостеприимства, номенклатуру, маршруты, туристов, заявки, а также записи независимых регистров «СрокиКонтроля», «НастройкиИнтеграций» и константу. Документы не создаёт.
- `Обеспечить(...)` уже даёт идемпотентность для справочников: поиск по наименованию, создание только при отсутствии.
- Все документы имеют табличные части, кроме «МаршрутныйЛист», «СобытиеМаршрута» и «ПретензияПоставщику». У «ТурыМаршруты» есть ТЧ «СтандартныйНаборУслуг».
- Обработчики проведения всех девяти документов пустые, поэтому движения регистров не формируются.
- `ТипыЗапросовТуристов.SLAЧасов` — Число(3,0): тридцать минут в нём не выразить.
- Фактическое содержимое базы не подтверждено: лог прошлого прогона утерян, обработка обёрнута в общий `Попытка`, поэтому прогон мог оборваться на середине.

## Goals / Non-Goals

**Goals:**

- Довести существующую обработку до полного демонстрационного набора без переписывания с нуля.
- Сделать наполнение устойчивым к частичному прогону: каждый блок в своей `Попытка`, каждый документ ищется по естественному ключу.
- Получить отдельный read-only инструмент проверки, пригодный для повторных прогонов и для защиты.

**Non-Goals:**

- Обработчики проведения и движения регистров — этап 4.
- Формы, роли, профили, отчёты на СКД.
- Очистка базы и генерация «с нуля»: набор только дополняется.

## Decisions

### 1. Расширяем `ЗаполнениеНСИ`, а не пишем вторую обработку

Альтернатива — отдельная обработка `ЗаполнениеДокументов`. Отклонена: пришлось бы дублировать справочные списки и порядок зависимостей, а идемпотентность документов всё равно опирается на справочники, созданные первой обработкой. Одна обработка = один прогон = один лог.

Логика остаётся в модуле формы: это текущая конвенция проекта и её уже вызывает `run-fill.ps1`. Перенос в объектный модуль дал бы возможность запускать обработку без формы, но потребовал бы менять способ запуска и разбираться с `/C` заново — выгоды для курсовой нет.

### 2. Каждый блок наполнения — в своей `Попытка`

Сейчас общий `Попытка` вокруг всего `ВыполнитьЗаполнение`: падение на валютах оставляет базу без сотрудников и туристов, а лог обрывается. Меняем на `Попытка ... Исключение` внутри каждой процедуры заполнения; ошибки копятся в лог, прогон продолжается. Итоговая строка — сколько блоков отработало и сколько упало.

### 3. Идемпотентность документов — по естественному ключу, а не по номеру

Номер документа присваивается автоматически с периодом «год», поэтому опираться на него нельзя. Для каждого вида определён естественный ключ, по которому документ ищется запросом перед созданием:

| Документ | Естественный ключ |
|---|---|
| ЗаказПоставщику | ЗаявкаНаТур + Поставщик + ДатаОжиданияПодтверждения |
| ПодтверждениеУслуги | ВходящийНомер |
| МаршрутныйЛист | ЗаявкаНаТур |
| СобытиеМаршрута | МаршрутныйЛист + ТипСобытия + ДатаВремяUTC |
| КорректировкаМаршрута | МаршрутныйЛист + СобытиеМаршрута |
| ЗаявкаТуристаНаМаршруте | МаршрутныйЛист + ТекстЗапроса |
| Инцидент | ЗаявкаНаТур + ТипИнцидента + ДатаИнцидента |
| ПретензияПоставщику | Инцидент |
| АктОКомпенсации | Претензия |

Альтернатива — счётчик «создать до N» — отклонена: при ручном удалении середины набора она создаёт дубли и неверно трактует частичный прогон. Ручная нумерация (`Автонумерация = Ложь`) отклонена: меняет поведение нумерации документов и упирается в длину поля «Номер».

### 4. Даты набора фиксированные

Все даты задаются литералами (сентябрь–октябрь 2026), а не считаются от `ТекущаяДата()`. Иначе повторный прогон через месяц создаёт другие документы и ломает идемпотентность, а правило «дата инцидента не позже текущей» перестаёт быть проверяемым. Инциденты датируются не позже 2026-10-01.

### 5. Три сквозных сценария на двадцать документов

Распределение (итого 20):

| Сценарий | Заявка | Документы |
|---|---|---|
| 1. Анталия, отель и трансфер | З-2026/001 | ЗаказПоставщику ×2 (отель, трансфер), ПодтверждениеУслуги ×2, МаршрутныйЛист ×1, СобытиеМаршрута ×2, КорректировкаМаршрута ×1, ЗаявкаТуристаНаМаршруте ×1, Инцидент ×1, ПретензияПоставщику ×1, АктОКомпенсации ×1 |
| 2. Дубай, отель и экскурсия | З-2026/002 | ЗаказПоставщику ×1, ПодтверждениеУслуги ×1, МаршрутныйЛист ×1, СобытиеМаршрута ×2, ЗаявкаТуристаНаМаршруте ×1 |
| 3. Хургада, экскурсия без подтверждения | З-2026/003 | ЗаказПоставщику ×1, Инцидент ×1 |

Сценарий 1 даёт полную цепочку «заказ → подтверждение → маршрут → событие → корректировка → запрос → инцидент → претензия → акт». Сценарий 2 — маршрут без инцидента. Сценарий 3 — заказ, который остался без подтверждения (статус «Отправлен») и инцидент в работе. Так в наборе есть и завершённые, и незавершённые состояния.

### 6. Значения справочников — по Дополнению, с точечной правкой типа

`СрокиКонтроля`: Номер 14, Трансфер 3, Экскурсия 7, Питание 10 дней (п. 5.4.1). Для «Страхование» и «Виза» Дополнение значений не задаёт — оставляем существующие, не выдумываем.

`ТипыЗапросовТуристов`: Медицинская помощь 0,5 ч, Диетическое питание 2 ч, Бытовой вопрос 4 ч, Прочее 24 ч (п. 5.4.2), плюс «Организация досуга» 12 ч и «Ранний заезд / поздний выезд» 8 ч для объёма.

Тридцать минут требуют дробного часа: `SLAЧасов` расширяется с Число(3,0) до Число(4,2). Альтернатива — хранить 1 час — искажает требование. Правка метаданных минимальная и не затрагивает структуру.

### 7. Проверка — отдельная read-only обработка

Внешняя обработка `ПроверкаДанных` с тем же способом запуска (`/Execute`, путь лога в `/C`), но без единого `Записать`. Проверяет:

1. количества по справочникам и документам против целевых;
2. пустые обязательные ссылки (явный список реквизитов на объект — прозрачнее рефлексии по `ПроверкаЗаполнения`);
3. ссылки на помеченные на удаление объекты;
4. правила п. 5.3: даты, суммы, соотношение взыскания и требования;
5. наличие строк в табличных частях.

Вердикт `PASS`/`FAIL` пишется последней строкой лога. `run-check.ps1` дописывает размер `1Cv8.1CD` (из PowerShell — из 1С файл базы не прочитать) и возвращает код 1 при `FAIL`, чтобы проверку можно было вставить в скрипт прогона.

### 8. Справочник «Пользователи» остаётся одним элементом

Соблазн добить его до 15 «сотрудников организации» есть, но справочник — не список людей: у него единственный реквизит `ИмяПользователяИБ`, он существует для условий RLS «текущий пользователь = этот». Учётная запись в базе ровно одна (`Администратор`), поэтому и зеркало одно. Записи без реальных учёток дали бы строки, которые никуда не ведут, — то же самое, что несвязанные записи, только проверкой ссылок не ловится.

Разнообразие по людям и должностям даёт «Сотрудники»: 15 человек на все шесть значений перечисления «Должности». Учётные записи и зеркала заводятся вместе с профилями групп доступа (остаток этапа 3) — там же появится смысл их различать.

### 9. Бэкап перед прогоном

Перед изменением метаданных и наполнением копируется `db/КурсоваяРабота/1Cv8.1CD` в `db/backup/` с датой в имени. Откат — восстановление копии при закрытых сеансах.

## Risks / Trade-offs

- **Прошлый прогон мог оборваться на середине** → наполнение идемпотентно по элементам и по естественным ключам документов, поэтому частичный набор просто дополняется.
- **Один общий `Попытка` скрывал ошибки** → разносим по блокам и пишем каждую ошибку в лог; итоговая строка показывает число упавших блоков.
- **Ручное удаление элемента из середины набора** → естественные ключи не ломаются, но количество упадёт; проверка покажет расхождение «факт из цели».
- **Файловая ИБ не принимает строки длиннее 1024 символов** → тексты описаний и шаблонов держим короче лимита.
- **Правка `SLAЧасов` требует загрузки конфигурации и `UpdateDBCfg`** → окно без сеансов, лицензия на одно место; выполняется до наполнения.
- **Фиксированные даты набора устареют** к защите → это демо-данные, «свежесть» не требуется; при необходимости даты сдвигаются правкой литералов и повторным прогоном с чистой базой.
- **Проверка не видит движения регистров** — их нет по определению; после этапа 4 проверку нужно расширить.

## Migration Plan

1. Закрыть все сеансы 1С, скопировать `1Cv8.1CD` в `db/backup/`.
2. Правка `SLAЧасов` в исходниках → загрузка XML в базу → `UpdateDBCfg`.
3. Пересборка `build/ЗаполнениеНСИ.epf` и новой `build/ПроверкаДанных.epf`.
4. `epf/run-fill.ps1` → прогон наполнения.
5. `epf/run-check.ps1` → вердикт; лог сохраняется в `docs/`.
6. Откат при необходимости: остановить сеансы, восстановить копию `1Cv8.1CD`.
